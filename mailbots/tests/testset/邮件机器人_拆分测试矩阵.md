# 邮件机器人 · 拆分（多行 / .xls）测试矩阵

**用途**：给 opencode 重构邮件机器人时，验证「运单号」与「ATB」两类邮件的**多行 / .xls 拆分**是否正确——重点看**拆分结果**（一封→拆几封、每封含哪些行/附件）和**转发结果**（转发给谁）。

**配套产物**：`test_fixtures/`（38 个 .eml 夹具 + `records.csv` + `manifest.json`）。夹具由 `build_testset.py` 生成，校验由 `validate_testset.py` 完成（已全部通过）。

---

## 0. 必须先知道：现状 vs 目标行为

> 这是本次测试要补的核心能力。**当前线上代码并没有真正做拆分**，测试集预期是针对「重构后目标行为」写的。

### 运单号 WAY_A —— 现状（代码实锤）
- `Waybill_Robot.run()` 第 595–617 行：解析 xls 得到 `rows`（多行），但**只取 `rows[0]`** 做匹配。
- 第 656 行调用 `build_forward(p["raw"], "WAY_A")`，该函数（`Draft_Forward_Robot.py:527`）是**整封原样转发**（原样重装 html/plain/附件，不按行拆、不按公司分组、不生成小 xls）。
- 结论：**当前一封运单号邮件只按第一行箱号匹配一个公司、整封原样发出，完全没有"按公司拆多行 + 生成小 xls"**。

### 运单号 WAY_A —— 目标行为（本测试集预期）
1. 解析 xls 全部 `rows`（每行 = 客户编码 + 箱号 + 运单号）。
2. 对每行 `match_record`（v2 规范，解析范围 `状态<>'退舱' AND is_deleted=0`）。
3. 按「外部公司」分组：有外部收件人的公司 → 一封**邮件**（含仅其名下行的**小 xls** + 仅其行的**正文表格**）；无外部收件人的内部子公司 → **仅企微通知**，不收邮件。
4. 退舱行（`is_box_cancelled`）→ **跳过**，不转发也不报警。
5. 未命中行（客编不在库）→ **报警 / 进待确认**（依实现）。

### ATB —— 现状即目标（业务约束不同）
- `Atb_Robot.py` 第 12 行注释明确：**「无多箱号拆分：每封 ATB 均为单箱号」**——但 `extract_boxes` 支持从 HTML 表格抽多个箱号，第 663 行 `for box_no, extra_info in boxes:` 会对**每个箱号各发一封完整原样邮件**。
- ATB 邮件是 HTML/纯文本正文，**无 .xls 附件**，所以**没有 .xls 拆分**，只有「多箱号 → 逐箱号各发一封整封原样」的拆分（不裁剪内容，因业务要求"按原内容转发、标题不改"）。
- 路由：`resolve_recipients(box_no, company)` 三级回退（箱号精确 → 公司 DEFAULT → 无配置跳过）。

## 3. opencode 怎么用这套测试集

1. **分类/匹配层**：用 `manifest.json` 的 `type/category/tier/action` 断言每封的分类与匹配档（草单 T0–T7、运单号 WAY_A/WAY_B 等）。
2. **拆分层（本次重点）**：对 `split` 字段存在的 13 个夹具，断言：
   - `email_parts`（外发邮件封数）与实际生成邮件数一致；
   - 每封外部邮件的**小 xls 行数 / 正文表格行数** = `parts[].rows` 对应数量；
   - `wecom_only_parts` = 仅企微通知的公司数；
   - `skip_rows` / `skip_boxes` 确实被跳过（如 W08 退舱、A05 无路由）；
   - `alarm_rows` 走报警/待确认（如 W09 未知客编）。
3. **转发层**：用 `forward.emails`（外部收件人语义）与 `forward.wecom`（内部企微对象）核对实际收件人。
4. **xls 解析**：W01–W09 的 xlsx 是 `openpyxl` 生成的真实多行文件，可直接喂给解析器端到端验证（不再用占位字节）。
5. **records 基准**：`records.csv` 同时喂养草单匹配、运单号匹配、ATB 箱号→公司映射；解析范围铁律 = `状态<>'退舱' AND is_deleted=0`。
