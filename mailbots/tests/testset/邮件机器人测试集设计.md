# 邮件机器人重构 · 测试集设计

> 芙蕾雅 2026-08-26 设计，供 opencode 重构后回归测试使用。
> 配套夹具由 `build_testset.py` 生成于 `test_fixtures/`（`manifest.json` 含每条预期结果）。

## 一、目标与范围

测试集覆盖**全部 5 类邮件**及各自的**分类 / 匹配 / 路由 / 边界**情况，用于验证重构后的机器人行为是否与既定规范一致：

- 草单（Draft）：A/B/C1/C2/W 五分类 + T0~T7 八档匹配 + 退舱/软删排除
- 运单号（Waybill）：WAY_A 按外部公司拆分转发
- 运踪（Tracing）：按 train 号扇出、xls 不解析
- DSK：箱号在 HTML 表格，按箱号拆分
- ATB：箱号在 HTML 或主题回退，原内容转发

> 注：本测试集编码的是**目标行为（v2 规范）**，即重构后"应当"的表现，而非线上旧代码的现状。

## 二、目录结构

```
test_fixtures/
├── records.csv            # 匹配基准数据（16 行，含退舱/软删/复用等边界）
├── draft_nums_seed.txt    # B 类判定所需的"已转过草单"数字段台账种子（260709001）
├── manifest.json          # 每条夹具的预期 {type, category, tier, action, note}
├── draft/   (17 .eml)
├── waybill/ (5  .eml)
├── tracing/ (3  .eml)
├── dsk/     (3  .eml)
└── atb/     (3  .eml)
```

**夹具约定**：附件仅用**文件名**参与判定（机器人靠文件名正则识别草单/箱号），正文与附件内容均为占位，无需真实二进制。运踪 xls 机器人不解析只转发，故为占位 `.xls`。

## 四、解析范围铁律（草单/运单号共用）

匹配加载 records 时必须：

```sql
WHERE 状态 <> '退舱' AND is_deleted = 0
```

D07（退舱）、D08（软删）即验证此点：两封草单件因对应记录被排除而"未命中"，最终走 T4 报警而非错误转发。

## 五、如何使用

1. **加载基准**：将 `records.csv` 导入测试用 `yxo.db` 的 `records` 表（列：客户编码/箱号/开票子公司名称/状态/is_deleted）。
2. **B 类种子**：将 `draft_nums_seed.txt` 的数字段（260709001）注入"已转草单台账"，使 D03 判为 B。
3. **跑夹具**：把各 `.eml` 喂给对应机器人解析器，断言其产出与 `manifest.json` 的 `category/tier/action` 一致。
4. **断言重点**：
   - 草单：分类(A/B/C1/C2/W) + 匹配档(T0~T7) + 动作(forward/pending/alarm/record_only)
   - 运单号：外部拆分 vs 内部仅企微
   - 运踪：整封扇出、不解析 xls
   - DSK/ATB：箱号提取来源（HTML / 主题回退）

## 六、覆盖率自检

- 邮件类型：草单 / 运单号 / 运踪 / DSK / ATB ✅ 全覆盖

- 匹配八档：T0/T1/T2/T3/T4/T5/T6/T7 ✅
- 边界：退舱排除、软删排除、箱号复用、跨到站、无客编、无箱号、多附件、无 xls、分段 ✅
- 解析范围铁律：✅（D07/D08）
