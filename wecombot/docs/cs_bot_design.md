## 3. 指令解析原则（✅ 按第5点确认）

### 3.1 宽容解析（非严格格式）

实际输入五花八门，解析器按“**先抽取实体，再判断意图**”处理，不要求空格和标准格式：

```text
可识别的等价输入示例（客编 CQWLJT260819001-D，箱号 TGBU1234567）：
  CQWLJT260819001-D 更新 箱号 TGBU1234567
  CQWLJT260819001-D更新箱号TGBU1234567
  更新CQWLJT260819001-D箱号：TGBU1234567
  CQWLJT260819001-D 箱号 TGBU1234567
  给CQWLJT260819001-D更新箱号 TGBU1234567
```

解析步骤：
1. **实体抽取**：用正则从全文抓客编（`[A-Z]{2,8}\d{6,}(-[A-Z0-9]+)?`）、箱号（`[A-Z]{4}\d{7}`）、班列号（`WB\s?\d{2,5}`）、字段名（箱号/封号/草单/报放单/随车/状态/备注…）。
2. **意图判断**：含“更新/改/修改/换成/录入/增加”→ 更新；含“查/查询/看看/搜索”或只有单实体 → 查询；含“撤销/撤回/取消上一步”→ 撤销；含“发邮件/发送邮件”→ 邮件流程。
3. **标点归一**：全角冒号/空格/换行一律清洗。
4. **无法判断时反问**，绝不猜着执行写操作。

### 3.2 “客编 箱号”歧义处理（✅ 按第7点确认）

输入只含 `客编 + 箱号` 两个实体、无动词时：

| 数据库状态 | 行为 |
|------------|------|
| 该客编已有该箱号 | → 查询，展示该记录 |
| 该客编箱号为空 | → 更新箱号（回执确认） |
| 该客编已有**不同**箱号 | → 反问三选一 |

反问文案：

```text
⚠️ 客编 CQWLJT260819001-D 已有箱号 TGBU9999999，
与你发的 TGBU1234567 不一致。请回复：
1 — 更新为新箱号 TGBU1234567
2 — 按新箱号重新搜索
3 — 展示该客编的全部信息
```

### 3.3 撤销指令（✅ 新增）

- 每个用户维护一个**操作历史栈**（最近 10 步写操作：更新字段、存文件、标记已发等）。
- 指令：`撤销` / `撤回` / `撤销上一步`。
- 回执：

```text
↩️ 已撤销上一步操作：
[更新] CQWLJT260819001-D 箱号 TGBU1234567 → 恢复为 TGBU9999999
```

- 已发送的邮件不可撤销（回复说明），存文件撤销 = 移入回收暂存目录（不物理删除）。

## 4. 四类场景

### 4.1 查询记录

输入：客编 / 箱号 / 客编_箱号 / 班列号 / 公司关键词（均可夹杂在自然语句中）。

反馈（多条）：

```text
找到 2 条记录：

1) CQWLJT260819001-D | TGBU1234567
   班列：WB611 | 发班：2026.08.15 | 太平洋
   口岸：阿拉山口 | 目的站：杜伊斯堡 | 状态：已发车
   草单✅ 报放单❌ 随车✅

2) …

回复序号看详情。
```

### 4.2 更新数据

支持字段：箱号、封号、草单、报放单、随车、状态、备注、入堆场、入站。宽容解析见 §3.1。

回执：

```text
✅ 已更新：
CQWLJT260819001-D（太平洋）
箱号：（空）→ TGBU1234567
目录已创建：2026\08\8.15 WB611\CQWLJT260819001-D_TGBU1234567\随车|报放
（回复“撤销”可回退）
```

### 4.3 存文件（✅ 按第6点确认）

**场景 A：先丢文件过来（无说明）**

1. 文件下载到暂存区 `BOT_TEMP_DIR`，回复询问：

```text
📎 已收到文件「装箱单.pdf」，请告诉我用途：
- 存档：回复「客编 随车」或「客编 报放」
- 马上发邮件：回复「发邮件 客编」（发送后文件自动存档）
- 发错了：回复「取消」
```

2. 用户回复后归档 / 进入邮件草稿 / 丢弃。

**场景 B：先发文字，再发文件（批量）**

1. 用户先发「CQWLJT260819001-D 随车 收文件」（或类似），机器人回复：

```text
📥 好的，接下来发送的文件将暂存。
发完后回复「完毕」或「确认」，我会统一存入
CQWLJT260819001-D 的随车文件夹。
```

2. 中间收到的每个文件回执「已暂存 (n)：文件名」。
3. 收到「完毕/确认」后统一入库并汇总回执；收到「取消」则清空暂存。

**存档回执**：

```text
✅ 已存入 3 个文件 → 2026\08\8.15 WB611\CQWLJT260819001-D_TGBU1234567\随车\
1. 装箱单.pdf
2. 报关单.pdf
3. 照片.jpg
该记录「随车」状态已更新为：已到
```

### 4.4 发邮件（草稿-预览-编辑-确认）

#### 触发

`发邮件 客编` / `发邮件 客编_箱号`（自然语句中含“发邮件”+客编即可）。

#### 草稿生成

- 主题：`{班列号}_{客编}_{箱号}_随车资料`
- 收件：luohua@yxologistics.com（可指令改）
- 抄送：documents-wb@yxologistics.com（可指令改）
- 发件：操作人自己的邮箱
- 附件：**默认自动带上该记录随车文件夹的全部文件**（报放不发邮件）

#### 预览格式

```text
📧 邮件草稿 #1
━━━━━━━━━━━━━━━
主题：WB611_CQWLJT260819001-D_TGBU1234567_随车资料
收件：luohua@yxologistics.com
抄送：documents-wb@yxologistics.com
发件：maoxiaoyang@cqtransit.com

正文：
您好，
附件为 WB611 班列 CQWLJT260819001-D / TGBU1234567 随车资料，请查收。

附件（2）：
1. 随车清单.pdf
2. 装箱照片.jpg
━━━━━━━━━━━━━━━
指令：确认发送 / 更新正文 xxx / 删除附件 1 /
新增附件（直接发文件给我）/ 查看文件夹 /
更新收件 xxx / 更新抄送 xxx / 取消
```

#### 编辑指令（✅ 按第 2、3、4、8 点确认）

| 指令 | 行为 |
|------|------|
| `更新正文 您好，……` | “更新正文”之后的**全部内容**整段替换正文 |
| **直接发文件** | 草稿态下收到文件 = 新增附件（等同存文件通道，微信转发文件同样适用，无需路径） |
| `删除附件 2` | 按序号删 |
| `替换附件 1`（然后发文件） | 提示“请发送新文件”，收到后替换 |
| `查看文件夹` | 展示该客编随车文件夹的文件列表，回复序号即可加为附件 |
| `更新收件 a@b.com` | 改收件人（多个用逗号/空格分隔） |
| `更新抄送 a@b.com` | 改抄送 |
| `确认发送` / `发` / `OK` | SMTP 发送 |
| `取消` | 放弃草稿（暂存附件保留询问是否存档） |

每次编辑后**重新返回完整预览**。

`查看文件夹` 回复示例：

```text
📂 CQWLJT260819001-D_TGBU1234567\随车（3 个文件）：
1. 随车清单.pdf（已在附件）
2. 装箱照片.jpg（已在附件）
3. 委托书.pdf
回复「加 3」把第 3 个加入附件。
```

#### 发送后快照

```text
✅ 邮件已发送
主题：WB611_CQWLJT260819001-D_TGBU1234567_随车资料
收件：luohua@yxologistics.com | 抄送：documents-wb@yxologistics.com
发件：maoxiaoyang@cqtransit.com | 附件：2 个
时间：2026-08-15 10:35:02
台账「邮件发送」已更新为：已发
草稿期间新收的文件已同步存档至随车文件夹。
```

## 5. 会话状态机

每个用户独立维护会话状态（内存 + 落盘 JSON，重启不丢）：

```text
IDLE          — 空闲，接受任意指令
DRAFT_EMAIL   — 邮件草稿编辑中（文件=加附件，文本=编辑指令）
AWAIT_FILES   — 批量收文件中（文件=暂存，"完毕"=入库）
AWAIT_CHOICE  — 等待反问回答（1/2/3 或指令）
```

状态超时 30 分钟自动回 IDLE 并提示。

## 6. 实现拆分

| 模块 | 内容 |
|------|------|
| `cs_bot/parser.py` | 实体抽取 + 意图识别（§3） |
| `cs_bot/session.py` | 会话状态机 + 操作历史栈（撤销） |
| `cs_bot/query.py` | 查询/更新 yxo.db（复用 records 表） |
| `cs_bot/files.py` | 媒体下载（自建应用 media/get + 客服 media）、归档、目录规则 |
| `cs_bot/mailer.py` | 草稿管理 + SMTP 发送 + 台账回写 |
| `cs_bot/kf.py` | 微信客服通道：sync_msg 拉取 / send_msg 回复 / 身份绑定 |
| `server.py` | handle_message 分发：普通消息→通道A；kf_msg_or_event→通道B |
