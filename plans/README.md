## 已拍板的决策（2026-08-09）
| 决策点 | 结论 | 说明 |
| --- | --- | --- |
| 远程可达 | **ZeroTier 为主**（已可用），iNode 为白天备用 | 不需要 Tailscale；iNode 方向相反，不能当梯子 |
| 3389 要不要找数科部 | **不需要** | RDP 走 ZeroTier 虚拟网卡，公司防火墙看不到；只需改服务器本机防火墙 |
| 梯子代理客户端 | **Clash Verge** | 本机用 GUI 调规则，服务器跑 mihomo 内核（无 GUI） |
| 远程通道形态 | **抽拉式分层**：SSH → RDP → RustDesk → 智能插座 | 逐层降级，任一层可用即可救火 |
| 唤醒 | **智能插座**（BIOS 已设通电自启），WoL 不需要 | 仅作最后手段，优先 SSH 软重启 |
| n8n 跑哪 | **服务器 Active 生产 + 本机 Inactive 设计台** | 两边不可同时 Active，否则重复触发 |
| CI 测试 | **GitHub Actions**，不用 n8n | 零穿透、零维护，结果直接显示在 PR |

## ⚠️ 三个必须记住的坑
1. **RDP 会话抢占**：Win 客户端版只允许一个活动会话，RDP 连入会锁物理桌面。若小叽依赖 GUI 自动化会被打断。断开时用 `tscon 1 /dest:console` 推回控制台。→ 这也是把 SSH 排在 RDP 前面的原因。
2. **空密码禁止远程登录**：Windows 策略 `LimitBlankPasswordUse=1`，空密码账号只能本地登录。须改为「设密码 + `netplwiz`/`Autologon` 自动登录」，既保留开机直达桌面，又让 RDP/SSH 可用。
3. **硬断电会损坏 SQLite**：智能插座拔电时若 `yxo.db` 正在写入，可能损坏生产库。须先开 WAL（`PRAGMA journal_mode=WAL`），并把插座定位为最后手段。

1. **GitHub Actions 自动测试** — 零依赖、纯本机可做，立刻有用
