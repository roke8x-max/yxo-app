# YXO 订舱数据管理平台

> 重庆物流集团 · 一套由业务部门自研、4 名同事日常使用的**订舱数据管理 + 邮件协同 + 企微通知**系统。
> **这份文件是项目总览**：讲清"这是什么、怎么跑、东西在哪、该看哪份文档"。各模块的细节见各自目录下的 `README.md`。

---

## 一、这是什么（三十秒）

集团原用**飞书多维表**做订舱数据底账，问题有三个：飞书客户端太卡（同事电脑配置一般）、API 有配额限制、自动化脚本读写它不可靠。

于是自研了这套系统，**用「浏览器里的 Excel 式表格 + 本地 SQLite」替代飞书**，并在此之上长出两件自动化：**邮件自动转发**和**企微通知**。

**对外叙事基线**：集团系统（吉联供应链平台）做业务主流程；本系统做「**自动入口 + 低成本看录统计 + 整箱散舱维度 + 企微人机协同**」。两套互补不重复——**不要建议重建 OMS，也不要建议切回飞书**。

## 二、三大支柱

| 支柱 | 干什么 | 代码在哪 | 现状 |
|---|---|---|---|
| **① 邮件机器人**<br>（自动入口） | 监听 4 个企业邮箱，把**草单 / 运单号 / 运踪 / DSK / ATB / 退信**邮件结构化，转发给**外部客户公司** | `mailbots_next/`（新，主线）<br>`mailbots/`（旧，见其 README） | 旧系统**仍在生产运行**；新系统已就绪但**尚未切换** |
| **② 订舱数据管理平台**<br>（主站，:5011） | 浏览器表格查看 / 编辑订舱数据；看板 / 统计 / 回收站 / 舱单导入 / 托书 / 价格 | 仓库根目录：`app.py`、`admin_api.py`、`manifest_engine.py`、`templates/`、`static/` | **live**（同事日常使用的就是这个） |
| **③ 企微机器人**<br>（:5001） | 通知（转发 / 待办 / 日报 / 告警）+ 命令回调 | `wecombot/` | live，但**除作者外基本无人使用** |

### 数据流

```
       4 × @cqtransit.com 邮箱
              │ IMAP
              ▼
  ① 邮件机器人（mailbots / mailbots_next）
     读取 → 提取 → 路由 → 判定 → 转发 → 通知 → 去重 → 落库 → 日志
              │
     ┌────────┼────────┐
     ▼        ▼        ▼
  转发外部   写 yxo.db   企微通知
  客户公司              （→ ③ :5001）
                          │
  ② 主站 :5011 ──读写──► yxo.db（records = 订舱真源）
```

## 三、怎么跑起来

```powershell
# ① 主站（本机）
venv\Scripts\python.exe app.py          # 或双击 start.bat，自动建 venv、查端口、开浏览器
# → http://localhost:5011；同事经 nginx 反代 http://<内网地址>:5000/yxo/

# ② 新邮件机器人（必须在仓库根执行；默认干跑，加 --live 才真发信）
python -m mailbots_next.serve
python -m mailbots_next.serve --live

# ③ 企微机器人
wecombot\start_server.bat                # pythonw 拉起，监听 :5001
```

⚠️ **不能** `python serve.py`（绝对导入会 `ModuleNotFoundError`），必须用 `-m`。

### 跑测试

🔴 **同一台机器上只用同一个解释器**（装依赖和跑测试必须是同一个，否则会出现"我这边绿、你那边红"）：

```powershell
$PY = "<这台机器的 python.exe 绝对路径>"
& $PY -m pip install -r requirements-dev.txt
& $PY -m pytest -q -p no:cacheprovider
```

- ⚠️ 不要用 `py -3.13`、也不要用编辑器自带的 Python。
- ⚠️ **不要在任何文档里写死"当前多少用例"**——用例数每次 PR 都会变。判据是 **`0 failed`**。
- ⚠️ 换机器时：先 `& $PY -c "import sys; print(sys.executable)"` 自检并写进报告。

## 六、数据边界（一句话版）

| 库 | 位置 | 谁读谁写 |
|---|---|---|
| `yxo.db` | 生产 `D:\YXO_DATA\yxo_app\data\` | **订舱真源**。主站 + 新旧邮件机器人 |
| `auth.db` | 主站 `data/` | 权限模块专用，与 `yxo.db` 分离 |
| `bot_config.db` / `dedup.db` | `mailbots_next/data/` | 机器人自有配置与去重 |
| `cs_bot.db` | 生产 `D:\YXO_DATA\WeComBot\data\` | 企微 |

⚠️ **两个 `bot_config` 不是一回事**：`init_bot_config.py` 建的是 **`yxo.db` 内**的表（主站后台用）；`mailbots_next/data/bot_config.db` 是**独立的机器人配置库**。**勿混库。**
⚠️ 凭证（`secrets.json`、`config_local.py`、`accounts.json`）**绝不入库 / 打印 / 进测试快照**。
⚠️ 生产库以**只读**为主；任何写操作前**先备份并取得确认**。

## 八、这套系统的成功与边界（写给未来的人）

- **它之所以跑得起来，唯一原因是「邮件转发」这个业务场景足够高频**——不做就立刻出事。
- **同事真正在用的是「在线表」式的查看界面**，不是写入功能。
- 已实证：**企微机器人除作者外无人使用**；同事宁愿保持现有操作节奏。
- ⇒ **加新功能之前先过两条判据**（详见 `AGENTS.md`）：**人会不会用**（痛 / 立刻后果 / 更省力）、**数据支不支持**（谁维护 / 靠人填的填写率往往不足）。
