# 验收圣经 · 怎么让不懂技术的人也能亲手验证

> **给**：毛骁洋（可长期复用，不限本项目）
> **用途**：任何自动化 / 新功能 / 改生产数据的事，**动手前照这份走**。
> **结构**：第一部分是**你自己怎么做**；第二部分是**要告诉智能体怎么做**（可直接复制）。
> **由**：雪儿｜**日期**：2026-10-06

---

# 第 0 章 · 为什么需要这份（30 秒）

**一句话**：智能体验证智能体，防不住它们**一起看不出问题**。

- 你用隔离对话、隔离记忆、换网页版来防"自己给自己打分"——**这个做法有效**，它防住了同一个上下文的自证。
- 但它防不住的是：**同一批模型看同一个东西，会一起觉得没问题。**
- 所以真正独立的验证者只有一个：**你，加上真实业务事实。**

**结论**：验收设计的目标**不是让你看全部**，而是把**只有你能判断的那一小部分**交给你，并且压到最小、最具体、最不需要技术。

> **智能体负责"有没有做对"；你负责"这是不是我们要的"。**

# 第一部分 · 你自己怎么做

## 第 1 章 · 三条铁律（背下来）

### 铁律一：只看「对答案」，不看实现

| ❌ 不接受 | ✅ 只接受 |
|---|---|
| 代码、测试输出、"跑通了" | **一行一条真实事件的对照表** |
| "准确率 94%" | **"这封邮件系统判成 X，你打开邮箱看是不是 X"** |
| "已证实""应该没问题""理论上" | 能让你**自己动手核对**的原始依据 |

> 理由：百分比你没法判断够不够好，代码你看不懂——**只有具体案例你能判断。**

### 铁律二：你的任务只有两件

1. **抽查对答案**（10 条起）
2. **专门找错**

**不要试图"确认全对"**——那既费劲又不必要。**找错比确认容易得多，而且只有你能找。**

### 铁律三：开闸判据 = **你找不出反例**

不是"智能体说没问题"，不是"测试全绿"，是**你抽查 + 找错之后，挑不出一个确凿的错**。

## 第 2 章 · 第一阶段：影子期（只观察，不落库）

### 2.1 你要做的第一件事：让智能体进"影子模式"

**影子模式 = 只做判定 + 只写日志，绝不写业务数据、绝不对外发送。**

任何会**写生产数据**或**对外发东西**的改动，第一步都必须是这个。

> 你其实已经在用两次了：权限模块先部署、开关=0 只观察不拒绝；新版邮件机器人默认干跑、加 `--live` 才真发信。**把它变成规矩，而不是每次凭感觉决定。**

**怎么要求**：直接复制 [§6.1 的话术](#61-让智能体做影子期) 发给智能体。

### 2.2 智能体必须交出的东西：一张「人话对照表」

**形态**（这就是你要的东西，别的都不要）：

| # | 日期 | 原始依据（你自己能核对的定位） | 系统判定 | 系统依据 | **我认为对不对** |
|---|---|---|---|---|---|
| 1 | 2026-08-22 | `maoxiaoyang@` · 草单号文件夹 · 「回复:运单草单_YXO-2026-734…」 | 草单已获得 | 渝新欧回复确认了 | ☐ 对 ☐ 错 ☐ 看不懂 |
| 2 | 2026-08-23 | `yangyawen@` · 运单号文件夹 · 「…CQWLJT260827003-Kol…」 | 运单号已获得 | 邮件正文含客编 | ☐ 对 ☐ 错 ☐ 看不懂 |
| 3 | 2026-08-24 | `maoxiaoyang@` · 随车文件夹 · 「…773 1 x Ready for pick-up…」 | 随车资料已发送 | 你方已发出附件 | ☐ 对 ☐ 错 ☐ 看不懂 |

**这张表的硬要求**（写进给智能体的话术里）：

1. **一行 = 一条真实邮件/单据**，不许合并、不许抽样省略、不许只给"代表样本"。
2. **"原始依据"必须精确到你能自己找到**：账号 + 文件夹 + 主题（或日期 + 发件人 + 主题）。
   → 判据：**你若按这一列找不到那封邮件，这张表就是不合格的。**
3. **"系统判定"必须是人话**（如"草单已获得"）。
   → **禁止**出现变量名、函数名、代码标识、`true/false`、`enable`。
4. **判定为"跳过 / 无结论 / 拿到不确定"的行也必须列出来**，不许隐藏。
5. 表里要有一节：**智能体自己列出"它没把握的情况"**。

### 2.3 你拿到表之后怎么做

#### 步骤 1：抽查 10 条「对答案」

**做法**：按下面的顺序各抽一轮，共 3 轮：

| 轮次 | 抽哪些 | 为什么 |
|---|---|---|
| 第 1 轮 | 表里**最新**的 10 条 | 最近的你最熟 |
| 第 2 轮 | 表里**最早**的 10 条 | 防止它只在近期做对 |
| 第 3 轮 | **智能体自己说"没把握"**的那些 | 这是它自己承认的薄弱点 |

**每一行你要做的三件事**：
1. 按"原始依据"去邮箱/系统里**找到那条**；
2. 看"系统判定"**对不对**；
3. 在最后一列打勾（对 / 错 / 看不懂）。

**你会看到什么 / 卡住怎么办**：

| 情况 | 说明什么 | 怎么办 |
|---|---|---|
| 按"原始依据"**找不到**那条邮件 | 这张表不合格 | 退回，要求它给出**能定位到具体邮件**的依据 |
| "系统判定"**看不懂** | 它没用人话 | 退回，要求重写成业务语言 |
| 判定**明显错了** | 系统还没成熟 | 记下这一条，进步骤 3 |
| 打了很多"看不懂" | 这张表对你无效 | 退回重做，直到你能独立判断每一行 |

#### 步骤 2：专门找错

**不要试图确认全对，只找错的。** 技巧（按效率排序）：

1. **先看"同一种判定出现很多次"的行** —— 批量性错误最常见；
2. **再看智能体说"没把握"的那些**；
3. **看边界情况**：邮件很短、没附件、主题异常、发件人是陌生的、同一票来回好几封、日期跨月。

**找到一条就够**——记下来，先别管别的。

#### 步骤 3：判定

| 结果 | 结论 |
|---|---|
| 找到 **≥1 条确凿的错** | **停，不开闸。** 把那条给智能体，让它**修完重跑整个影子期**（不能只修那一条） |
| 3 轮抽查全对 + 找错找不到 | 可以进第 3 章 |
| 只是"看不懂"多 | 不算错，但**表要重做**——你做不了的验收等于没有验收 |

> ⚠️ **一个容易骗到自己的坑**：抽查全对，可能是你**抽得太集中**。所以一定要跑完上面 3 轮，别只抽一轮。

## 第 3 章 · 第二阶段：开闸

**开闸 = 让它真正开始写数据。**

### 3.1 开闸前，必须问它三个问题（照着问，答不上来就不开）

1. **开闸后第一次写库，会改哪些表、哪些字段？**
2. **如果写错了，怎么撤回？**（要**具体动作**，不接受"可以回滚"四个字）
3. **开闸后，我怎么知道它写对了？**（要一条**你能自己看**的检查，例如"表上哪一列会被填上、你打开哪一页能看到"）

### 3.2 开闸后的第一天，你自己做一次抽查

打开主站，看那几个字段**是不是真的被填上了**、**值对不对**。

> 这是你唯一需要做的"技术动作"——**看表**。不需要看代码、不需要看日志。

### 3.3 出事怎么办

- 先让它**停下**（说"停"即可）；
- 再问："现在库里被写坏了多少、怎么回到今天早上？"
- **不接受**"应该没事"。

## 第 4 章 · 永久清单：每次都要问智能体的 5 个问题

> 建议贴墙上。**这 5 个问题回答不了，就不该开工。**

| # | 问题 | 它在防什么 |
|---|---|---|
| 1 | 你这个判定**依据的数据从哪来**？**谁在维护那份数据**？ | 防"基于没人填的字段做自动化"（做出来 80% 的数据都是空的） |
| 2 | 这个改动**会写生产数据吗**？**会对外发东西吗**？ | 决定要不要先走影子期 |
| 3 | 如果做错了，**我怎么发现**？**怎么恢复**？ | 防"坏了不知道、知道了回不去" |
| 4 | 这件事**对我有什么立刻的好处**？（不是"更先进"） | 防"做出来只有作者自己用" |
| 5 | 你说的"完成"，**我自己能验证吗**？拿什么验？ | 防"报告说完成、实际没有" |

## 第 5 章 · 危险信号清单（听到就退回）

| 它说了这个 | 为什么危险 |
|---|---|
| "已证实" / "应该没问题" / "理论上" | 不接受结论，只接受**实跑证据 + 具体案例** |
| 只给百分比，不给具体案例 | 你无法判断 |
| 对照表里出现**代码词 / 变量名** | 那张表不是给你看的 |
| "原始依据"你**找不到** | 你无法独立核对，等于没验 |
| 没列出"它没把握的情况" | 掩盖了薄弱点 |
| 问它"怎么撤回"答不上来 | 没有回滚方案 |
| "这次改动很小，不用影子期" | 小改动也会写生产数据 |

## 第 6 章 · 可以直接复制的话术

### 6.1 让智能体做影子期

```
【任务】为「____（填要做的事）」做影子期验证。

硬约束：
1. 只读来源数据，只做判定，把判定结果写到一张对照表里。
2. 绝对不得写任何业务数据；绝对不得对外发送任何邮件/消息。
3. 不得修改任何现有代码逻辑（除新增这个影子脚本/开关本身）。
4. 做完停下等我验收，不要自行推进。

交付物必须包含：
- 一张对照表（格式见下）
- 你实际跑的命令原文
- 处理了多少条、各种判定各多少条
- 单独一节：列出你「没有把握」的情况

对照表格式（一行 = 一条真实邮件/单据，不许合并、不许抽样省略）：
| # | 日期 | 原始依据（要让我能自己找到：账号+文件夹+主题） | 系统判定（用人话，禁止代码词） | 系统依据（一句话） | 我认为对不对 |
最后一列留空给我填。

原话提醒：看不出问题不等于没问题。你的任务是让我能自己核对，不是让我相信你。
```

### 6.2 让智能体改进对照表（当你看不懂 / 找不到时）

```
这张对照表我用不了，原因：____（例如"原始依据我找不到那封邮件" / "系统判定我看不懂"）。
请重做：
1.「原始依据」必须精确到我能按它找到那封邮件（账号 + 文件夹 + 主题，或日期 + 发件人 + 主题）；
2.「系统判定」必须用业务语言，禁止任何变量名、函数名、代码标识、true/false；
3. 判定为"跳过/无结论"的行也要列出来，不许隐藏；
4. 重做后仍需附上：命令原文、条数统计、你没把握的情况。
```

### 6.3 让智能体开闸

```
影子期我已核对通过，现在可以开闸。开闸前先回答三个问题：
1. 开闸后第一次写库，会改哪些表、哪些字段？
2. 如果写错了，怎么撤回？给我具体动作（命令或操作步骤），不接受"可以回滚"。
3. 开闸后我怎么知道它写对了？给我一条我自己能看的检查（打开哪一页、看哪一列）。
另外：开闸后先只处理一小批（例如 5 条），停下等我确认，再放开全量。
```

### 6.4 两份独立验证（防"一起看不出问题"）

```
同样的输入，请你独立给出你的判定。不要参考其他任何智能体的结论。
产出格式与我给另一方的完全一致（同样的人话对照表）。
```

> **怎么用**：把同一件事丢给**两组互不通气的智能体**（不同对话、不同工具、甚至不同网页版），拿回两张表。
> **你只看它们不一致的那些行**——那些是最可能有问题的地方。你的注意力又少一半。

## 第 7 章 · 一页纸总结（真要记住就记这一页）

1. **任何会写生产数据的事，第一步都是"只观察不落库"。**
2. **验收看"对答案"，不看实现**：要一张"一行一条真实事"的人话对照表。
3. **你只做两件事**：抽查对答案（最新 10 条 / 最早 10 条 / 它说没把握的）+ 专门找错。
4. **找不到反例才开闸**；开闸前问三件事：改什么、怎么撤、我怎么知道它对了。
5. **每次开工前问那 5 个问题**；听到"已证实"就退回。
6. **一句话**：智能体负责"有没有做对"，**你负责"这是不是我们要的"**。
