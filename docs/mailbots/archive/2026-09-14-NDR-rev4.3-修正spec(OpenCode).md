## 1. G1【🔴 必修】`_fetch_uid` 去掉"序号回退"；uid 不可得时绕开 handled 索引

### 1.1 问题（洋/ds 判定：本轮最严重，属"静默漏退信"）

`bounce_handled` 表以 `(account, uid)` 为 PK。`_fetch_uid` 在 `(UID)` 取不到 UID 时**回退返回序号**：

```python
    try:
        return int(num)          # ← 危险：序号不是稳定标识
    except Exception:
        return None
```

IMAP **序号会随 expunge 漂移**：今天序号 5 是 A 邮件；删除几封后序号 5 变成 B 邮件。于是 B 撞上 A 的 handled 记录 → `is_bounce_handled` 命中 → **被静默跳过、永不处理**。等于**用幂等索引自己制造漏退信**。

### 1.2 修法（**两处都要改，只改一处仍会漏**）

> ⚠️ 只把"序号回退"删掉会变成 `uid=None`，而现有 `_poll_one` 在 `uid is None` 时是**直接 return**（跳过整封）——**照样漏信**。必须同时改这个分支。

**改动 1 `_fetch_uid`**：解析失败一律返回 `None`，**删除 `int(num)` 回退**；docstring 同步改（说明返回真 UID 或 None）。

**改动 2 `_poll_one`**：`uid is None` 时**照常处理**，只是**不读也不写** handled 索引：

```python
def _poll_one(conn, acct, num, stats):
    uid = _fetch_uid(conn, num)          # None = 拿不到真 UID
    if uid is None:
        # 拿不到稳定标识 → 绕开 handled 索引：照常处理（最坏重复处理一次，
        # 下游有 forward_log.bounced 与 error_queue UNIQUE 兜着，不会重复转发）。
        _log.warning("Bounce: no UID, handled index bypassed | acct=%s seq=%s" % (acct, num))
        increment_counter("bounce_uid_missing")
    hdr = _fetch_payload(conn, num, "(BODY.PEEK[HEADER])")
    ...  # 预筛 / 全文 / is_ndr 均不变
    if uid is not None and is_bounce_handled(acct, uid):
        stats["deduped"] += 1
        return
    ...
    outcome = _handle_ndr(acct, ndr, stats)
    if uid is not None:
        mark_bounce_handled(acct, uid, "", ndr.get("forward_id") or "", outcome)
```

要点：
- **绝不 `return`**：uid 不可得 ≠ 该封不是 NDR。
- `stats` 仍保持 **6 字段**（`processed/requeued/unknown/skipped_non_ndr/deduped/errors`），观测走 `increment_counter("bounce_uid_missing")`，**不要新增统计字段**（会破坏既有断言）。
- `ignored`（delayed/delivered）分支的 `mark_bounce_handled` 同样加 `if uid is not None:` 保护。

### 1.3 已知残留（登记，不阻塞）
uid 不可得时同一封会被每轮重复处理：
- **已匹配上 forward_log 的**：`forward_log.bounced == 1` → `_handle_ndr` 返回 `dup`，**不重复告警** ✓
- **unknown 的**：会每轮重复告警一次。
- 更彻底的做法是把 handled 键改为 **NDR 自身的 `Message-ID`**（表里已有 `message_id` 列，目前恒写 `""`）——**本次不做**，与 §4 一同登记。

## 2. G2【🟡 修】把节流抽成 `_bounce_poll_due`，让用例测到真代码

### 2.1 问题
`test_f4_bounce_poll_throttled_via_sweeper` **在测试里把节流条件抄了一遍**（`if (now - _last) >= POLL_SEC ...`），并未驱动 `run_sweeper` → **生产节流若被删，该用例照样通过**。这是"测试覆盖了测试自己"，不构成回归锁。

### 2.2 修法
抽出**纯函数**，`run_sweeper` 调用它：

```python
def _bounce_poll_due(now: float, last_ts: float) -> bool:
    """距上次轮询是否已达 BOUNCE_POLL_SEC。纯函数，便于直测。"""
    return (now - last_ts) >= BOUNCE_POLL_SEC
```

`run_sweeper` 内：
```python
        if BOUNCE_MONITOR_ENABLED:
            now = time.monotonic()
            if _bounce_poll_due(now, _last_bounce_poll_ts):
                _last_bounce_poll_ts = now
                try:
                    poll_bounces()
                except Exception as e:
                    _log.error(f"bounce poll tick failed: {e}")
```

### 2.3 测试要求（**关键：不得再复写条件**）
1. **纯函数直测**：`_bounce_poll_due(t, t - BOUNCE_POLL_SEC)` → `True`；`_bounce_poll_due(t, t - BOUNCE_POLL_SEC + 1)` → `False`；边界相等 → `True`。
2. **驱动真 `run_sweeper` 跑 2 轮**（这才算真回归锁）：
   - `monkeypatch` 掉 `serve.time.sleep`：**第 2 次调用时**把 `serve._shutdown_event` 置位，使循环在第 2 轮末退出（避开无限循环）；
   - 设 `BOUNCE_MONITOR_ENABLED=True`、`BOUNCE_POLL_SEC=9999`、`_last_bounce_poll_ts=float("-inf")`；`patch` 掉 `serve.poll_bounces`（计数）与 `serve.sweep_once`；
   - 断言：`poll_bounces` **恰被调用 1 次**（首轮轮询、次轮被节流）。
   - 说明：若 `time.sleep` 打桩困难，可另用"把 `_shutdown_event` 换成 `is_set()` 前两次返回 False、第三次返回 True 的假对象"实现；**但绝不允许退回"在测试里抄一遍 if 条件"**。

## 3. G3【🟡 顺手修，1 行】`_last_bounce_poll_ts` 初值

`time.monotonic()` 是**自开机秒数**，`0.0` 初值在 `uptime < BOUNCE_POLL_SEC`（默认 300s）的主机上会被判成"距上次不足 300 秒" → **首轮被跳过**（最多延后一轮）。

**改**：`serve.py` 初值 `0.0` → **`float("-inf")`**（保证进程启动后首轮必轮询）。

## 4. G4【⚪ 登记不修】预筛残留缺口 —— 补一条"已知限制"用例 + README 登记

**背景**：`_looks_like_ndr_headers` 在「**无任何 Content-Type 标记**（非 `multipart/report`/无 `report-type`/无 `delivery-status`）+ **From 非 postmaster/mailer-daemon** + **Subject 无关键词**」时会返回 `False` → 该封真 NDR 被跳过。洋拍板：**极罕见，登记不修**（要彻底覆盖就得回到"全量下载全文"，等于放弃性能优化）。

**要做两件事（都不是修功能）**：

1. **加一条 characterization 用例**——把该限制**显式钉住**，将来谁改预筛都会立刻被提醒：
   ```python
   def test_known_limitation_neutral_from_no_marker_is_skipped():
       """【已知限制 · 登记不修】形态为「无 Content-Type 标记 + 中性 From +
       无关键词 Subject」的真 NDR 会被预筛跳过 → 漏判。
       这是为性能有意接受的取舍（彻底覆盖需全量下载全文）。
       本用例不是待修 bug，而是把该边界显式记录；若将来预筛改动使本用例失败，
       必须先重新评估该取舍。"""
       hdr = ("From: notify@example-mta.com\r\n"
              "Subject: Message 12345 could not be delivered\r\n"
              "Content-Type: multipart/mixed; boundary=\"x\"\r\n")
       assert _looks_like_ndr_headers(hdr) is False   # ← 记录现状（非期望修复）
   ```
2. **README「技术债（登记，未实现）」表加一行**（接在 F5-1/F5-2 后）：
   - 内容：预筛对「零标记 + 中性 From + 无关键词」形态的真 NDR 会漏判；
   - 为什么不修：该形态极罕见；彻底覆盖需放弃 header 预筛、回到全量下载全文；
   - 何时再做：若真实出现此类漏判（以 `unknown` 告警或缺件投诉为线索），或引入更廉价的过程化判定手段时。
