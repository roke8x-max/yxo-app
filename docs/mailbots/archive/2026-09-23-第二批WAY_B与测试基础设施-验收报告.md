## 5. 🔴 我新发现的一个真问题（**既有，不只影响本轮**）

**现象**：同一人会被发**两条相同**的企微消息。
**复现**（我的探针，假 client 计数）：

```
场景 A：responsible == OPS_OWNER → _notify_by_name 调用 2 次 → ['毛骁洋', '毛骁洋']
场景 B：兜底（OPS, OPS）        → _notify_by_name 调用 2 次 → ['毛骁洋', '毛骁洋']
```

**根因**：`OPS_OWNER_EMAIL = maoxiaoyang@cqtransit.com`，而 `seed_owner_mapping` 里 **「太平洋」和「港九港铁」的负责同事正是 `maoxiaoyang@cqtransit.com`** ⇒ 这两家公司的**任何通知**（`send_forwarded` / `send_alarm` / `send_pending` / 本轮新增的 `send_waybill_rejected`）都会得到 `[maoxiaoyang, maoxiaoyang]`，而 `_send_now`（`notify.py:236`）**逐个收件人循环、不去重** ⇒ 发给同一人两次。

**影响面**：不是本轮引入的（`send_alarm` 等一直如此），但本轮的 waybill_rejected 也继承；8 家客户里有 2 家归运维本人 ⇒ 属于会实际发生的情况。
**修法**（1 行，一次修好所有通知类型）：`_send_now` 里对 `recipients` 去重（如 `for recipient in dict.fromkeys(recipients):`）。
