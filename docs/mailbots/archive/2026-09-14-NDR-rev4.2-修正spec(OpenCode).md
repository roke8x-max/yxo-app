## 1. F1【正确性，必做】候选搜索不得用 HEADER 定向搜索替代全量 UNSEEN

### 1.1 问题

现状 `core/bounce.py::_candidate_seqnos`（约 :272-281）：

```python
typ, data = conn.search(None, 'UNSEEN HEADER Content-Type "delivery-status"')
if typ == "OK":
    return data[0].split() ...        # ← 直接返回，不再扫全量
# 只有 search 抛错/非 OK 才回退：
typ, data = conn.search(None, "UNSEEN")
```

两个事实叠加，造成**覆盖性漏判**：

1. **IMAP `SEARCH HEADER <field> <string>`（RFC 3501 §6.4.4）只匹配消息的顶层信头**；MIME 部件里的信头属于**正文**，不参与匹配。
2. **`SEARCH UNSEEN HEADER Content-Type "delivery-status"` 是 `SEARCH UNSEEN` 的子集**——它永远不可能返回全量 `UNSEEN` 扫不到的消息。

所以拿它当主路径，**只可能丢候选、不可能多**。具体漏的是：**顶层 `Content-Type` 不是 `multipart/report`（如 `multipart/mixed`，把 `message/delivery-status` 嵌在正文里）的 NDR** —— 这类 NDR 匹配不到该搜索，而因为 search 返回 `OK` 也不会回退，于是**从头到尾不会被看到**。rev4 原本扫全量 `UNSEEN` 是能抓到的 → 覆盖性回归，正好砸在"绝不漏退信"的初衷上。

### 1.2 修法（二选一，推荐 A）

**A（推荐，最简且无歧义）**：`_candidate_seqnos` 直接返回全量 `UNSEEN`：

```python
def _candidate_seqnos(conn):
    """候选 = 全部未读。绝不使用 HEADER 定向搜索做替代：
    SEARCH ... HEADER 只匹配顶层信头，是 UNSEEN 的子集，
    用它替代会漏掉顶层非 multipart/report 形态的 NDR。"""
    typ, data = conn.search(None, "UNSEEN")
    return data[0].split() if data and data[0] else []
```

删掉那条 HEADER 搜索及其回退日志（连同相关注释）。

**B（若一定要保留该搜索）**：只能作**叠加取并集**（先 `UNSEEN`，再 HEADER 搜索取并集、按序号去重），**不得替代**。但注意 §1.1 已证明它是子集 → 并集恒等于 `UNSEEN`，即等于 A 且多做一次无用网络请求。**故不建议选 B。**

### 1.3 成本说明（为什么删得起）

真正压住流量的是**头部预筛**（`_looks_like_ndr_headers`，只对像 NDR 的才取全文），**不是**这条搜索。删掉后每轮每账号多出的只是"对每封未读取一次 `BODY.PEEK[HEADER]`"（约 1–2 KB/封）。要再降负载，见 §4。

## 3. F3【小】purge 改为每天一次

`purge_old_bounce_handled()` 现在挂在**每轮 poll 末尾**（`bounce.py` 约 :325-328，即每 5 分钟一次 DELETE）。表很小、无害，但没必要。改为**每日一次**：在 `poll_bounces` 内用模块级"上次清理日期"判断（`datetime.now().date()` 变了才跑），或复用 `run_sweeper` 的每日时机。**保留 try/except 包裹，失败只 WARN 不影响轮询。**

## 4. F4【缺口，必做】`BOUNCE_POLL_SEC` 是死配置——轮询节流要真正生效

**实测**：`BOUNCE_POLL_SEC`（`settings.py:79`）只被定义与导出，**全仓无任何代码引用**。实际节流逻辑在 `serve.py::run_sweeper`：

```python
if BOUNCE_MONITOR_ENABLED:
    poll_bounces()          # ← 每个 SWEEP_INTERVAL_SEC(=300s) 都跑
```

即"轮询周期可配"是**假的**，实际固定 5 分钟（288 次/天）。

**修法**：让 `BOUNCE_POLL_SEC` 真正生效——用模块级"上次轮询时间戳"判断，距上次不足 `BOUNCE_POLL_SEC` 则跳过本轮（`run_sweeper` 或在 `poll_bounces` 入口处实现皆可，二选一并在报告中说明）。
**默认值保持 `SWEEP_INTERVAL_SEC`（不改行为）**；生产若要降负载，设 `BOUNCE_POLL_SEC=900`（15 分钟）即可把轮询量降到 1/3，无需改代码。
