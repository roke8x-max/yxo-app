## 1. 调查结论（三问三答）

### 问 ①：`WAY_A` / `WAY_B` 有没有进过 DB？

**新系统：不进。**（三条证据，都是实读代码）

1. `forward_log` 表**没有 tier / note 列** —— `store.py:329-335` 的 INSERT 列出全部列：
   `forward_id, message_id, row_key, account, folder, uid, subject, sender, date_hdr, raw_hex, to_list, cc_list, sent_by, sent_at, bounced`，**tier 不在其中**；而且 WAY_B 这类**根本不转发**。
2. `error_queue` 的 `stage` / `error_type` 取值是一组固定值（`ingest`/`identify`/`extract`/`row`/`routing`/`act` × `INGEST_EXCEPTION`/`IDENTIFY_EXCEPTION`/`UNCLASSIFIED`/`EXTRACT_EXCEPTION`/`EMPTY_ROWS`/`ROW_EXCEPTION`/`NO_ROUTE`/`MISSING_CREDENTIALS`/`ACTION_FAILED`），**不含 tier**；`extra` 列只用来存 `{"notified_manual_at": …}`（`dedup.py:171-175`），生产代码**没有任何 `add_error(..., extra=…)` 调用**。
3. tier 只进**日志**（`log_decide`）。

**老系统：进了，而且是真实数据。**

| 位置 | 实测 |
|---|---|
| 生产 `MailBots/data/waybill_forward_ledger.db` → `processed_mails.category` | 🔴 **`WAY_A` 55 行 / `WAY_B` 6 行** |
| 仓库内 `mailbots/data/forward_log.db` → `forward_log.note` | 🔴 **801 行**含 `WAY_`，样例 `WAY_A 拆分转发(default, 1行)` |
| 生产其它命中文件 | `summary_digest_waybill.jsonl.sent`、`waybill_dryrun_report.txt`、`logs/waybill_2026-08-04.log`、`pending_queue.db.bak_*` |
| 老系统展示层 | `draft_pending.py:68` 有映射 `{"WAY_A": "运单号下发", "WAY_B": "单证驳回"}` ⇒ **老系统是"存代号、展示时翻译"** |

⇒ **结论**：新系统改名**不会**产生"历史数据对照"问题；但**老系统的台账/摘要归档里仍是代号**。若将来要做跨系统对照或迁移，需要一份**映射说明**（见 §4）。

## 2. 范围建议（**需你拍板**）

### 2.1 必做（本批）

新系统侧把 `WAY_B` 这个 tier 改成描述性名。

### 2.2 不做

- **老系统 `mailbots/`**：① 它**还在生产跑**，任何改动都是生产风险；② 它**即将退役**；③ 它还牵着 `tests/testset/`（那套测试集是按代号写的）⇒ 改它收益极低、风险不小。
- **历史归档文档与日志**（见 问③ B 类）：改了等于篡改历史记录。
- **实施方式**：老系统的代号**保持不动**，只在 §4 留一份映射表。

### 2.3 ⚠️ 一个必须先知道的事实

**新系统里根本没有 `WAY_A`** —— 全仓 `mailbots_next/` grep `WAY_A` = **0 命中**。
新系统只有 `WAY_B` **一处 tier 字面量**（`decide.py` 的守卫 + `serve.py` 的 `log_decide`）。

⇒ 也就是说："带 WAY_A 的全是老系统"（xls 拆分转发那条路径在新系统里就叫普通的 waybill 流程，落到 T1–T7）。
**所以本批在新系统侧其实是个小活**；真正"到处是代号"的是老系统（但那些不建议动）。

### 2.4 可选项：要不要顺带把其余 tier 也改成描述性名？

新系统当前的 tier 字面量（`decide.py` / `serve.py`）：`T0`×3、`T1`×2、`T2`–`T7` 各 1、`TRACE_HIT`×2、`TRACE_MISS`×2、`MANUAL`×1、`UNKNOWN`×2 —— 约 **17 处**；测试里另有 4 个文件引用（`test_core.py` / `test_h2_h3.py` / `test_round5.py` / `test_waybill_rejected.py`）。
**技术上是安全的**（已核实 **tier 不入 DB**，只进日志与测试断言），但改动面比 `WAY_B` 大得多，且会同时改到 4 个测试文件与若干文档。
⇒ **建议：分两步** —— 本批只做 `WAY_B`（最小、可立即收口）；`T0–T7` 那批**另立一项**，等你想清楚要什么命名风格（例如 `T4 → no_code_box_cancelled` 这类）再动。
