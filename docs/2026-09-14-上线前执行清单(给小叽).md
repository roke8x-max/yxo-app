## 二、环境变量核对（**3 项必做** + 1 项可选，先做）

用 PowerShell（管理员）。设完**新开一个窗口**再核对。

### 2.1 必设：`YXO_DB_PATH` → 指向本地盘

**为什么**：新系统会**回写** `yxo.db`（DSK/ATB 时间戳、运踪记录）。这个变量的**代码默认值是网络路径** `\\10.0.199.184\yxo_data\yxo_app\data\yxo.db`。写库走 SMB、且会启用 SQLite 的 WAL 模式，而 **SQLite 官方明确 WAL 不支持网络文件系统**，典型报错是 `attempt to write a readonly database`。更麻烦的是写库失败会被误判成"发信失败"，导致**同一封邮件重发给客户**。

机器人就跑在这台机器上，所以用本地盘路径指向同一份库即可。

```powershell
[Environment]::SetEnvironmentVariable('YXO_DB_PATH','D:\YXO_DATA\yxo_app\data\yxo.db','Machine')
```

核对（**新开窗口**执行）：

```powershell
[Environment]::GetEnvironmentVariable('YXO_DB_PATH','Machine')
```

- ✅ 期望看到：`D:\YXO_DATA\yxo_app\data\yxo.db`
- ❌ 如果回显是 `\\10.0.199.184\...`，或**一片空白** → 没设成功。**空白等于没设**，运行时会落到代码里的 UNC 默认值。重做。

> 若新服务是用 nssm 起的，把 `YXO_DB_PATH=D:\YXO_DATA\yxo_app\data\yxo.db` 加到该服务的环境变量里（`nssm set <服务名> AppEnvironmentExtra ...`），别只设 Machine 级——两种方式选一种，别漏。

### 2.2 必设：`FORWARD_SINCE` → 上线当天日期

**为什么**：这是**防呆门禁**。新系统第一次以 live 模式启动时，如果不设这个，它会把**邮箱里所有历史未读邮件**当成新邮件，**批量转发给外部客户**——这是事故级的。所以不设的话，服务会**直接拒绝启动**并提示你设。

```powershell
[Environment]::SetEnvironmentVariable('FORWARD_SINCE','2026-09-15','Machine')
```

⚠️ 把 `2026-09-15` 换成**实际切换那一天**（格式 `YYYY-MM-DD`）。填错成很早的日期 = 门禁形同虚设。

核对：

```powershell
[Environment]::GetEnvironmentVariable('FORWARD_SINCE','Machine')
```
- ✅ 期望：`2026-09-15`（实际切换日）
- ❌ 空白 → 新服务起不来，日志会提示 `Refusing to start in live mode without FORWARD_SINCE`

### 2.3 必不设：`BOUNCE_MONITOR_ENABLED`

**为什么**：退信监控本轮不上线（数科部退信邮箱/别名还没定，关联键也还没实测）。代码默认关闭，**只要不设这个变量就是关的**。

```powershell
[Environment]::GetEnvironmentVariable('BOUNCE_MONITOR_ENABLED','Machine')
```
- ✅ 期望：**空白**
- ❌ 若是 `1` → 删掉再重启：
  ```powershell
  [Environment]::SetEnvironmentVariable('BOUNCE_MONITOR_ENABLED',$null,'Machine')
  ```

### 2.4 可选：`INGEST_POLL_SEC`（收信轮询间隔，**默认 30 秒，一般不用设**）

**为什么有这个**：新系统靠**短周期轮询**发现新邮件（不再用 IDLE 推送）。`INGEST_POLL_SEC` 决定"隔多少秒扫一遍邮箱"，**代码默认 30**。

- **不用设**就能跑（最坏延迟 30 秒、平均 15 秒），**建议保持默认**。
- 只有在"邮箱里未读邮件特别多、轮询压力大"时才考虑调大（比如 60），代价是收信变慢、同事可能等不及去手动转发。
- ⚠️ **绝不要设成 0 或负数**：那会导致**完全不收信**（代码会 WARN 并回落到 30，但别依赖这个兜底）。

```powershell
# 想确认当前生效值（没设过就是空白 = 用默认 30）
[Environment]::GetEnvironmentVariable('INGEST_POLL_SEC','Machine')
```

> 新系统还会在 `mailbots_next\data\imap_state.json` 里记录"每个邮箱/文件夹读到哪了"（UID 水位线），用来保证不漏信。**这是运行数据，不要手工编辑、也不要删**（删了会触发一次全量重扫）。

### 7.1 停旧系统

🔴 **先记住"旧系统在哪"**（2026-09-17 实测确认，此处以前写得不明确）：

| 目录 | 是什么 |
|---|---|

**要停的是 `MailBots\` 那套机器人，不是 `yxo_app\`。** 下面每一步先看清"这个 pythonw 是从哪个目录起的"再动手。

```powershell
# ① 看现在有哪些 pythonw 在跑，并核对它们的启动时间（旧系统是 pythonw 起的）
Get-Process pythonw -ErrorAction SilentlyContinue | Select-Object Id,StartTime,Path

# ② 看 MailBots 目录下今天有没有被写过（有 = 它正在运行）
Get-ChildItem D:\YXO_DATA\MailBots -File -Force |
    Where-Object { $_.LastWriteTime -gt (Get-Date).Date } |
```
