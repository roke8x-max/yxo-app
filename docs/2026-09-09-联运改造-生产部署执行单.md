## 4.5 环境变量核对（上线前必查 · 零代码）

⚠️ 本节两项必须在上线前落实，否则新系统写库会踩网络路径的坑。依据：`2026-09-14-上线前必办spec(OpenCode)-写库路径与记账时序.md`。

### 4.5.1 必设：`YXO_DB_PATH` 指向本地盘

**为什么**：新系统会**回写** `yxo.db`（records 的 dsk/ATB 时间戳、tracing_log、tracing_snapshot），而这个变量在 `mailbots_next/config/settings.py:9` 的**默认值是网络路径**：

```
\\10.0.199.184\yxo_data\yxo_app\data\yxo.db      ← 默认值（不要用）
```

写库走 SMB、且 rw 连接会启用 `journal_mode=WAL`，而 **SQLite 官方明确 WAL 不支持网络文件系统**——典型报错就是 `attempt to write a readonly database`。旧系统 `mailbots/core/paths.py` 是**本地优先**（候选顺序 `D:\YXO_DATA` → UNC），新系统需要显式对齐。

**要设成**（机器人就跑在 10.0.199.184 本机，本地路径与 UNC 指向同一份库）：

```
YXO_DB_PATH=D:\YXO_DATA\yxo_app\data\yxo.db
```

**怎么设 / 怎么验**（⚠️ 按你实际的启动方式选一种）：

- **系统环境变量**（推荐，服务重启后自动生效）——PowerShell（管理员）：
  ```
  [Environment]::SetEnvironmentVariable('YXO_DB_PATH','D:\YXO_DATA\yxo_app\data\yxo.db','Machine')
  ```
  设完**新开一个窗口**核对：
  ```
  [Environment]::GetEnvironmentVariable('YXO_DB_PATH','Machine')
  ```
  → 你会看到 `D:\YXO_DATA\yxo_app\data\yxo.db`。
  → 若回显是 `\\10.0.199.184\...` 或是**空白**（空白 = 会落到代码里的 UNC 默认值）→ 没设成功，重来。

- **启动脚本（.bat）**：在 `pythonw` 那一行**之前**加一行
  ```
  set YXO_DB_PATH=D:\YXO_DATA\yxo_app\data\yxo.db
  ```

- **nssm 服务**：把 `YXO_DB_PATH=D:\YXO_DATA\yxo_app\data\yxo.db` 加进服务的环境变量（`AppEnvironmentExtra`）。

**上线后怎么确认真生效**：启动日志里若出现 UNC 相关 WARN（见 4.5.2 之外的 UNC 同步项）说明**仍是网络路径**；另可观察当天有无写库报错、以及每日 digest 里是否出现 `post_send_bookkeeping_failed`。

### 4.5.2 必不设：`BOUNCE_MONITOR_ENABLED`

**为什么**：退信监控（NDR）**代码默认关闭**（默认 `0`）。当前"数科部别名未回复 + 关联键（`X-YXO-Forward-Id` 能否随退信回来）尚未实测"，按洋的决定**本轮退信部分不上线**，确保不影响主转发链路。

**做法**：**不要**设置这个变量。条件成熟（关联键实测通过）后再设 `BOUNCE_MONITOR_ENABLED=1`。

**核对**：
```
[Environment]::GetEnvironmentVariable('BOUNCE_MONITOR_ENABLED','Machine')
```
→ 期望**空白**。若是 `1`，请删除该变量并重启服务。
