## A. 修法 A：影子期沿用客户端自报身份（解决 问题1 署名 + 问题2 筛选）

**拍板**：影子期不是"没有身份"，而是"**不校验身份**"。身份仍取前端传来的 `user`（旧「我是」下拉），只是不做登录校验、不做权限拦截。翻 1（AUTH_ENABLED=1）才切服务端登录身份。

**代码改动点（请核当前 main 代码，勿凭记忆）**：
- `auth/__init__.py` 的 `_auth_gate` 影子期分支：当前第 3 层无条件把 `g.identity` 换成 `_system_identity()`（username="system"）→ 这是根因。改为：**只改 `g.identity` 的构造来源**，影子期从前端自报的 `?user=` 参数取用户名，构造：
  `g.identity = SimpleNamespace(username=<前端 ?user= 值>, role="<占位，不参与判定>", permissions=<全部权限>, scope_type="all", companies=[])`
  ⚠️ **影子期不引入 role 映射表**：`role` 随便填、不参与任何判定；`scope_type="all"` 即不限制公司范围；`permissions` 给全部权限（影子期本就不拦截）。**不要让 OpenCode 去猜"自报 user → 哪个 role"的映射逻辑——根本没有这张表。**
  ⚠️ **字段必须与 G1–G8 的 identity 对齐（5 字段）**：此处显式补 `companies=[]`。G1–G8 的 identity 是 `(username, role, permissions, scope_type, companies)` 五字段，`resolve_scope` 等可能读 `.companies`；shadow 虽走 `scope_type="all"` 全量、不实际读它，但**字段必须在**，否则翻 auth 切换或任何读 `.companies` 的代码会因子对象缺属性报错。

  🔔 **落码边界提醒（发给 OpenCode 时口头也提一句）**：影子期 `username` 直接取 `request.args.get("user", "")`（等同旧版）。**若 `?user=` 为空，保持空字符串，不要兜底成任何默认值——尤其禁止 `or "system"`**。否则又回到"署名变 system"的 bug 老路（极端情况触发，但必须杜绝）。空就空，严格等同旧版行为。
- **修法 A 只改 `_auth_gate` 里 `g.identity` 的来源，不动 G1–G8 已改的调用点**：写接口里的 `user = g.identity.username`、以及 `/api/state` 按 `g.identity.username` 读写，全部**保持现状**。署名和筛选都从同一个 `g.identity.username` 取值，因此来源修好后**两者同时恢复**，无需再改调用点。
- 翻 1 分支保持现有服务端登录身份逻辑不变。
- **代价（洋接受）**：影子期「我是」下拉 UI 保留，翻 1 时一次性删干净（见 B 节）。

**验收**：影子期 PATCH 一行 → `updated_by` = 真实姓名（非 system）；四人各 `GET /api/state` 读到各自行，互不覆盖。

## B. 前端双模式（洋硬要求，红线）

**拍板**：前端通过 `/api/auth_meta` 返回字段感知当前模式，据此切两套 UI：
- 返回示例：`{ "mode": "shadow" | "auth" }`
- **影子期（AUTH_ENABLED=0）**：前端完全等同旧版——显示「我是」下拉、不弹登录窗、不挂 CSRF 头、未登录不跳转。
- **翻 1（AUTH_ENABLED=1）**：切新 UI——显示「当前用户 + 登出」、401 弹登录窗、挂 CSRF 头。

**代码改动点**：
- 后端 `/api/auth_meta`：返回 `mode`（取 `AUTH_ENABLED` 环境变量/配置，值为 `"shadow"` | `"auth"`），同时保留原返回的身份信息。
- 前端**在各页 `init()` 里统一判 `mode`**，不要散到多处：
  - 若 `mode === "shadow"` → 渲染「我是」下拉 + **不挂 CSRF 头** + **不弹登录窗**（等同旧版）；
  - 否则 → 走现有 auth 逻辑（登录态 UI + 401 弹窗 + 挂 CSRF 头）。
  - 建议抽一个公共判断（如 `applyAuthMode(mode)`）在 `/admin`、`/tuoshu`、`/manifest` 三页 `init()` 统一调用，**避免各页各写一遍导致行为漂移**。
- 🔴 **红线（最重要的一条）**：影子期绝对不能出现"弹登录窗、用户登不进去、又退不出、页面没法用"。自测时务必在 `AUTH_ENABLED=0` 下走一遍全流程。

## C. 问题 3：游客公司列表拆分（bug，洋拍板）

**根因**：`auth/schema.py` SEED_USERS 游客公司写成**顿号连写串**（如 `'太平洋、港九港铁'`），而 `yxo.db` 实际 `开票子公司名称` 是**独立取值**，`records_dao.py` 做归一化后精确比对 → 只有恰好独立的（保时达、联运）匹配，其余 6 家全漏。

**生产库实际取值（2026-10-10 查 `\\10.0.199.184\yxo_data\yxo_app\data\yxo.db`，records 共 3073 行）**：
| 取值 | 行数 |
|---|---|
| 同程配 | 1906 |
| 保时达 | 479 |
| 港九港铁 | 189 |
| 中欧木业 | 104 |
| 沙坪坝 | 85 |
| 太平洋 | 82 |
| 东盟 | 53 |
| 联运 | 4 |
| （NULL） | 164 |
| （空串） | 7 |

→ 游客是**一个账号**，`companies` 改为这 **8 个独立字符串**：`["太平洋","港九港铁","保时达","同程配","东盟","沙坪坝","中欧木业","联运"]`（洋 2026-10-10 确认：保持全 8 家、一个账号，覆盖全部下属单位）。落码以此为准。

**`visitor_demo`（已停用账号）**：同 bug，按洋拍板**直接删，不用修**（从 SEED_USERS 移除）。

**验收**：游客登录后 `/api/rows` 行数应≈全库有公司归属的 2876 行（3073 − 164 NULL − 7 空串 − 少数），而非仅 481（17%）。
