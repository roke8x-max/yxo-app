## 0. 本文的范围假设（如与预期不符，请先纠正再开工）

本文**不重写权限模块**（它已落码、模块化达标），只做三件事：

1. **上线**（生产至今未部署——见 §1.2）；
2. 按「**4 人自用、审计不严格**」这一已确认定位，**收敛范围**：该做的补齐，不该做的明确不做；
3. 补齐加固书里**写了但没落码**的一项，并处理两个**已登记未修**的缺陷。

> 如果你要的是别的（例如把 `auth/` 抽成独立包、或重做前端登录交互），本文不适用，请说明后重写。

## 1. 现状（全部实读代码 / 实测生产，行号可直接核）

### 1.1 已落码的部分（不要推翻）

- 权限模块是**内联包** `auth/`（8 个 `.py`），设计明示"本期内联、不抽包"（`docs/superpowers/specs/2026-09-21-permission-rbac-module-design.md:137`）。
- 硬约束成立：`auth/` **不 import 任何业务模块**（`auth/__init__.py:11-16`）。
- 外接点只有三处：`app.py:26`（`require_permission`）、`app.py:1668-1669`（`_init_auth(app)`）、`auth/__init__.py:158`（`before_request` 门禁）。
- 数据：单一 `data/auth.db`，与 `yxo.db` 分离（`config.py:152`）；7 张表 users/roles/permissions/role_permissions/sessions/audit/login_attempts（`auth/schema.py:37-82`）。
- 3 角色 10 权限；`visitor` 仅 `record:read` + `record:export`（`auth/rbac.py:44-60`）。
- 门禁唯一拦截层 = `@app.before_request`（`auth/__init__.py:71-113`），按 `(method, rule)` 查表，**未登记即 403**（`:94-95`）；页面 HTML 一律 public，权限只在 API 层（`auth/rbac.py:79-84`）。

## 2. 定位收敛：按「4 人自用 + 外部只读」确定做与不做

毛骁洋 2026-10-06 明确：**这套系统是开发给他和另外 3 位同事自己用的，审计不严格**；权限模块的真实价值在于**让外部（集团下属数科公司）能只读看数据**（`游客` 帐号）。

### 2.1 要做（越省摩擦越好）

1. **上线**：按 `docs/superpowers/specs/2026-09-30-deploy-handoff-combined.md` 执行，本文**不重复**其步骤。两次独立部署（B 先、A 后）的约束保持不变。
2. **减少登录摩擦**（这是"4 人自用"最直接的收益）：
   - 会话时长与「记住我」天数**放宽**：现为 `AUTH_SESSION_HOURS=12`、`AUTH_REMEMBER_DAYS=30`（`config.py:156-157`）→ 建议会话提到 **72 小时**。
   - 理由：4 人内网自用，频繁重新登录是纯摩擦，不带来安全收益。
3. **G1 落码**：`init_db(..., strict=True)`，缺必需环境变量时**直接 raise 拒绝启动**；`scripts/init_auth_db.py` 与 `auth/__init__.py` 均传 `strict=True`。生产绝不允许弱占位口令上线。
4. **G2 落码**：`visitor_demo` 在 `auth/schema.py` 的种子里**直接置 `disabled=1`**，不再依赖人工 SQL。
5. **G3 补齐**：给 `admin.html` / `tuoshu.html` 加上与 `index.html:205` 等价的登录弹窗与 `/api/meta` 401 处理。
6. **G4 修正**：把 `.gitignore:72` 的裸 `test_*.py` 改为精确忽略（或按目录开例外），使新测试文件能进版本库。
7. **G5 收口**：在 `requirements.txt` 声明口令哈希依赖；若选择 `pbkdf2`，则**在代码注释里写明这是有意选择**，避免以后被当成缺陷。
8. **G6 消除**：让路由权限清单只有**一处**定义源。视图内不再重复判断权限。
9. **G7 角色重划 —— 毛骁洋已于 2026-10-06 逐项拍板**：
   - **权威依据**：`docs/2026-10-06-角色与权限-勾选结果(确认版).md`（**以该文 §2 的逐人权限矩阵为准**，本 spec 不重复抄录）。
   - **结构性变更 ①**：**4 人（毛骁洋 / 韩文豪 / 杨雅雯 / 冯茜）全部 `scope=all`**（能看到所有公司）⇒ **数据范围不再是区分维度**。`config.py:166-171` 的 `USER_COMPANIES` **保留**，但用途唯一：邮件转发 / 企微通知的"这票归谁"路由，**不得**再用于数据隔离；数据隔离只对 `visitor` 有意义。
   - **结构性变更 ②**：**权限按人配置，废弃角色抽象**。给每人一个同名角色：`admin` / `hanwenhao` / `yangyawen` / `fengqian` / `visitor`。**不要保留 `manager`**（它现有语义"几乎全能"正是要消除的）。
   - **必须新拆的 4 项权限**（否则上面的矩阵做不到）：从 `record:write` 拆出 `data:import`（`/api/import`、`/api/import_upload`）、`options:manage`（`POST /api/field_options`）、`trash:purge`（`DELETE /api/trash/<int:rid>`）；从 `config:manage` 拆出 `train:manage`（`POST /api/train_status`）。
     - **边界**：回收站的**恢复**（`POST /api/trash/<int:rid>/restore`）与软删一样，**留在 `record:write`**。
     - `manifest:import` / `manifest:apply` 与 `admin:view` / `config:manage` 已经是分开的，**保持不动**。
   - **已拍板的要点**：冯茜排除在「价格维护 / 托书」之外是**有意为之**（维持）；`admin:view` **仅 `admin`**；`train:manage` = 专列的发运状态（服务于筛选），**4 人全给**。
   - ⚠️ **关键背景**：`manager` 现持有的 `manifest:apply` 覆盖 `/api/manifest/revert` 与 `/api/manifest/restore`，后者是**整库快照还原**（`manifest_engine.py:968-981`，源码注释自称"核弹级"）。
   - ⇒ **在角色重划落码并验收通过之前，不要把 `AUTH_ENABLED` 翻成 `1`**（否则等于把"整库还原"这颗按钮一次性发给 3 位同事）。
10. **G8 收敛**：删除死代码常量与过时注释（`admin_api.py:32` `ADMIN_USER`、`:36` `LIMITED_ADMINS`）；`tuoshu.html:158` 的前端硬编码名单改为**从服务端返回**；最终「谁能做什么」**只有一处定义**。
11. **⛔ G9 翻开关的硬前置：先给 `manifest.html` 补 CSRF（毛骁洋 2026-10-06 已确认，要求写入本 spec）**
    - **事实**：`auth/__init__.py:81-84` —— `AUTH_ENABLED=0` 时门禁**提前 `return`**，CSRF 与权限两层都不执行；`:88-90` —— 开关一开，CSRF 层立刻生效，而豁免清单只有一条：`auth/service.py:181` `CSRF_EXEMPT_PATHS = frozenset({"/api/stamp"})`。
    - **实测**：四个页面的 CSRF 头 —— `static/app.js` ✅、`templates/admin.html` ✅、`templates/tuoshu.html` ✅、**`templates/manifest.html` ❌ 零**（其 `:189-194` 是裸 `fetch`）。
    - **后果**：翻 `=1` 之后，`/api/manifest/upload`、`/api/manifest/apply`、`/api/manifest/revert`、`/api/manifest/restore` 会**全部返回 403**，舱单导入页当场不可用。
    - **要求**：
      1. **翻 `AUTH_ENABLED=1` 之前**，必须给 `manifest.html` 补上与其余三页等价的 CSRF 头（并一并补 401 处理与登录入口，见 G3）。
      2. 在**同一批验收**里给出证据：翻 1 之后，舱单上传 → 看差异 → 应用 → 回退/还原 **逐项实跑通过**（附输出）。
    - **安全边界（写明，避免误判）**：**"部署代码但开关保持 0"不会打断任何功能**，可以先部署、先观察。
    - **执行方式**：本条由执行方落码前，**再请芙蕾雅 / 小叽独立复核一次**（毛骁洋 2026-10-06 明确要求）。

### 2.2 不做（明确写下来，避免执行方"顺手"扩范围）

- **不做完整的审计能力**：不建审计查询界面、不做审计报表、不为审计完整性投入。`auth/audit.py` 现有的"审计失败绝不能打挂业务"的写法（`auth/audit.py:23`）**保持**。
- **不做权限运营界面**（角色/权限的增删改）。
- **不做细粒度字段级权限**。
- **不把 `auth/` 抽成独立包**（保持内联，设计已定）。
- **不改 `yxo.db` 表结构**。
- **不动 `AUTH_ENABLED` 的灰度语义**（默认关、dry-run 只观察不拒绝）。
- **不碰工单系统相关设计**（角色维度问题另行讨论）。

## 3. 验收标准

1. **G1**：清空必需环境变量后启动 → **进程直接失败并给出明确错误**，绝不写入 `yxo-dev-*` 占位口令。附实跑输出。
2. **G2**：全新库跑 `scripts/init_auth_db.py` → `SELECT username,disabled FROM auth_users WHERE username='visitor_demo'` 返回 `1`。
3. **G3**：未登录状态直接打开 `/admin` 与 `/tuoshu` → 页面能弹出登录框并登录成功（两个页面各附一次实跑/截图证据）。
4. **G4**：在 `tests/` 下新建一个 `test_xxx.py` → `git status` 能看见它（`git check-ignore -v` 不再命中）。
5. **G5**：`pip install -r requirements.txt` 一次装齐，`auth/service.py` 的哈希路径可运行；注释说明所选算法。
6. **G6**：`grep` 证明同一路由的权限要求只在一处定义；`tests/auth_gate_test.py` 全绿。
7. **回归**：`tests/auth_gate_test.py`（32 例）与 `mailbots_next/tests/` 全套通过。
8. **上线**：按 §2.1-1 的交接单执行后，`/api/csrf`、`/api/login`、`/api/auth_meta` 在生产返回 **非 404**（附探测输出）。
9. **G7**：按 `docs/2026-10-06-角色与权限-勾选结果(确认版).md` 落码，并逐项实测：
   - 用每个角色（`admin`/`hanwenhao`/`yangyawen`/`fengqian`/`visitor`）各一个测试账号登录，对该做的能做、该不能做的返回 **403**，输出一张**逐项实测表**；
   - **专门验证前端一致性**：没有某权限的人**看不到**对应入口（而不是看得到、点了报错）；
   - `admin.html` / `tuoshu.html` / `manifest.html` **三个页面都要有登录弹窗**（现只有 `index.html` 有）；
   - 证明 `manifest:apply`（含 `revert`/`restore`）、`price:manage`、`config:manage`、`data:import` 仅在 `admin` 名下；
   - 证明 `manager` 这个 key 已不再存在于代码中（或已明确标注为历史遗留且无人使用）；
   - **证明 `AUTH_ENABLED=1` 是在以上全部通过之后才翻的**（附时间顺序证据）。
10. **G8**：`grep` 证明「谁能做什么」只有一处定义；`admin_api.py:32/36` 两个死常量已删；`tuoshu.html` 不再硬编码名单。

## 4. 不在范围

- 工单系统的角色模型（`internal`/`partner` 与现有 `admin`/`manager`/`visitor` 是**两个维度**，不能复用同一字段；该议题另行讨论）。
- `auth.db` 归属与抽包时机（`docs/superpowers/specs/2026-09-21-permission-rbac-module-design.md:318` 已记为"届时再定"）。
- 前端整体重构、主站结构改造。
- 任何与 `mailbots*`、`wecombot` 相关的改动。

## 5. 给执行方的硬约束

1. **禁止 `commit` / `push` / 开 PR**，代码完成即停，报告等验收。
2. 用 `git add <具体文件>`，**禁止 `git add -A`**。
3. 分支名**扁平、不带斜杠**，从 `main` 切。
4. 报告必须附实跑证据：命令 + 输出末几行 + `文件:行号`。禁止「已证实」「应该没问题」。
5. **不得为了让测试变绿而放宽任何业务判据**（含权限判据）。测试红先定性：数据问题 / 环境问题 / 逻辑问题。
6. 测试不得连生产库；用临时库。
7. 发现计划外问题**只登记，不顺手修**。
8. 与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准并立即报告。
