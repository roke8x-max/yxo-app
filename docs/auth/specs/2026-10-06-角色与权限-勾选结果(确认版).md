## 1. 两项结构性变更（先读，否则会做错）

⇒ `config.py:166-171` 的 `USER_COMPANIES` **保留**，但用途唯一：**邮件转发 / 企微通知的"这票归谁"路由**。**不得**再拿它做数据隔离。
⇒ 数据隔离只剩一个用途：**外部游客**（另行确认范围）。

### 1.2 权限按人配置，**废弃"角色"抽象层**

4 个人之间的权限是**不同的**（见 §2），所以不要再用 `manager` / `staff` 这类抽象角色去套。

⇒ 建议做法：**给每人一个同名角色**，直接配置权限。

| 角色 key | 人 |

| `admin` | 毛骁洋 |
| `hanwenhao` | 韩文豪 |

- 现有 `auth/rbac.py:44-60` 的 `ROLES` 与 `ROLE_PERMS` 按此重写。
- **不要**保留 `manager` 这个 key（它现在的含义是"几乎全能"，正是要消除的东西）。若因兼容必须保留，需在代码注释里写明它**已不再是**"同事默认角色"。

## 3. 三个待确认点 —— **已全部确认（2026-10-06）**

| # | 项 | 毛骁洋的答复 | 落码结论 |

| 3.1 | 冯茜被排除在「价格维护 / 托书」之外 | **有意为之**。冯茜年龄较大、对这些兴趣不大；她愿意用主站，纯粹是因为它替代了以前凌乱的 WPS 在线表、一站式就能看所有数据 | **维持排除**。冯茜 = 只读为主 + `record:write` + `manifest:import`；不给 `price:manage` / `tuoshu:generate` |
| 3.2 | 第 11 项 `admin:view` | **同意"只给毛骁洋"**，并同意需要**专门做前端一致性验收** | `admin:view` 仅 `admin` 持有；验收必须实测"缺该权限时管理页的价格维护块能正常显示、其他标签不显示" |

> ⇒ 对产品方向的含义：**主站的核心价值是"查看"，不是"写入"。** 优化优先级应据此排序。

### 3.1 冯茜被排除在「价格维护」和「托书」之外 —— 是否有意？

### 3.2 第 11 项 `admin:view`（能不能进管理页）给谁？

- 杨雅雯 / 韩文豪要改价格，**接口层面只需要 `price:manage`**（`/api/admin/price*` 走的是 `price:manage`，见 `auth/rbac.py:132-138`）。

### 3.3 第 13 项 `train:manage` 给谁？

- 第 13 项管的是**看板上的「班列状态」下拉**（未发运 / 已发运 / 已完成）：前端 `static/app.js:2237-2240`，写入 `train_meta` 表（`app.py:596-610`）。含义是"这一趟班列整体走到哪一步"。
