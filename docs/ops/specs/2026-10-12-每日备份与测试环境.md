# 每日备份 yxo.db + 测试环境（2026-10-12 拍板）

> **给**：小叽（服务器侧执行）/ 芙蕾雅（验收）。
> **模块**：ops（部署 / 环境 / 发布）。
> **两条独立事项，不要混在一起做。**

---

## 一、每日自动备份 `yxo.db`

### 为什么（P0，数据安全）
- **回滚脚本不回滚数据库**（`rollback.ps1` 只回滚代码）。
- 现有数据库快照只在**舱单导入时**产生。
- 软删有回收站兜底，但**单元格被覆盖就完全无痕**。
- 生产库是**唯一真源**。

### 要做
1. **定时备份**：每日固定时间备份 `yxo.db`。
   - 用 SQLite 备份 API 或先 `PRAGMA wal_checkpoint(FULL)` 再复制（参考 `manifest_engine.py:740-747` 现成写法）。
   - 命名带日期：`backup/yxo_YYYYMMDD.db`。
2. **保留策略**：保留最近 N 份（**N 待毛骁洋定**，建议 14–30），超出自动清理。
3. **备份位置：必须本地盘**，不要放 SMB/UNC（历史上 SMB 写报过 `readonly database`）。
4. **启动迁移前也备份一次**（`init_db` / `migrate_db` 之前）。
5. **可发现**：主站页面显示"**最近一次备份时间**"。

### 验收（**必须含一次真实恢复演练**）
1. 手动触发 → 文件生成，大小合理（附 `dir` 输出）。
2. **恢复演练**：挑一份备份 → 在**非生产副本**上真实恢复 → 核对关键数据（`records` 行数、某条字段值）与备份时一致。**附完整命令与核对结果。**
3. 保留策略生效：造多余备份 → 跑清理 → 只剩 N 份。
4. 页面能看到"最近一次备份时间"。
> ⚠️ **只给脚本不算完成**——第 2 条不过，不算完成。

### 待毛骁洋定
保留几份？每天几点跑？备份目录放哪？（建议生产机本地盘，如 `D:\YXO_DATA\备份\`，可复用 `manifest_engine.py` 的 `BACKUP_DIR` 常量。）

## 二、测试环境（生产部署前的前置）

### 背景
权限模块 **G1–G10 已全部合入 main**（角色按人 / 单点路由权限 / strict 种子 / manifest CSRF / 影子期身份），但**生产尚未部署**（`5011` 的 `/api/csrf`、`/api/auth_meta` 仍 404）。毛骁洋要求：**先由小叽搭测试环境，验证通过后再谈生产**。

### 要做（小叽）
1. 在服务器搭一个**独立测试环境**（新目录，不动 `D:\YXO_DATA\yxo_app` 生产目录）。
2. 从 `main` 检出最新代码。
3. **部署但 `AUTH_ENABLED` 保持不设置（=0）**——这是"部署代码，不是开权限"。
4. 按 `docs/ops/specs/` 下既有的部署交付单执行（若已归档，以 `docs/auth/` 与 `docs/ops/` 的现行 spec 为准）。

### 验收（照验收圣经）
1. `/api/csrf`、`/api/login`、`/api/auth_meta` 在测试环境**返回非 404**（附探测输出）。
2. **开关仍为 0**：`/api/meta`、`/api/rows` 无需登录即可访问（行为与部署前一致），日志出现 `AUTH_DRY_RUN`。
3. 四页功能正常（人工点一遍）；影子期「我是」下拉按 `?user=` 正确显示（G10）。
4. **翻 `=1` 的前置全部就绪后再测翻闸**：G9（manifest CSRF，已合入）+ 角色重划（G7，已合入）+ G10 影子身份（已合入）——三项都在 main 上，测试环境可先做一次完整的"翻 1 演练"：
   - 翻 1 → 四页登录 → 未登录被拦 → 舱单上传/应用带 CSRF 成功 → **逐项附输出**。
5. 测试环境通过后，**是否部署生产 / 何时翻 1，由毛骁洋另行拍板**——不要自行推进。

### ⛔ 禁止
- **不得在测试环境未过之前动生产**。
- **不得自行翻 `AUTH_ENABLED=1`**（生产或测试环境都由毛骁洋确认后才翻）。
- 搭测试环境时**不要**把生产库路径（`YXO_DB_PATH` 等）指到生产库上——用独立副本。
