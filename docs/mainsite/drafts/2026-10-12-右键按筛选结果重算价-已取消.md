## 1. 需求原话
> 「右键菜单要加一个『对当前筛选结果全部重新算价』的功能，主要用于批量更新目标记录的价格。」

## 2. 现状（实读 `origin/main` = `34cfdb6`）

**右键菜单**（`templates/index.html:167-179`）现有算价两项：
| 菜单项 | `data-act` | 前端 | 后端 |
|---|---|---|---|
| 算价此行 | `price` | `priceRow()`（`static/app.js:1307`） | `POST /api/price/<rid>`（`app.py:899-919`） |
| 批量算价（所有未算价行） | `priceall` | `batchPrice()`（`static/app.js:1506-1512`） | `POST /api/price/batch`（`app.py:922-945`） |

**两条现有批量算价的真实口径（关键）**：
| | `/api/price/batch`（app.py:922） | `/api/admin/price/recalc`（admin_api.py:1095） |
|---|---|---|
| 范围 | **全库**，与筛选无关 | **按月**（`发班时间` 所属月 = 传参 month） |
| 覆盖 | 只补**空**价 | 空价 **或** `updated_by ∈ ("算价","批量算价","重算")`；**手填不动** |
| 退舱守卫 | ❌ **无** | ❌ **无**（只过滤 `is_deleted=0`） |
| 写入标记 | `updated_by="批量算价"` | `updated_by="重算"` |
| 审计 | 一条 summary | 一条 summary |

**前端"当前筛选结果"怎么取**：`getView()`（`static/app.js:494-501`）= `DATA.filter(passFilter)` + 班列类型过滤 + 排序 —— 筛选条件大量在**客户端**（搜索 / 包含 / 公司 / 月份 / 看板标签），**服务端复现不出来**。

👉 **结论**：新功能无法靠"传筛选参数"实现，必须由**前端把当前筛选后的 id 列表**传给后端。

## 3. 待拍板（5 条）

### P1 · 覆盖范围（最关键）
「重新算价」要覆盖到什么程度？
- **(a) 只补空**：与现有 `/api/price/batch` 同口径（但限定当前筛选）。
- **(b) 只覆盖"机器写的"**：沿用 `recalc` 的 `MACHINE=("算价","批量算价","重算","筛选重算")` 口径，**手填价一律不动**。← 芙蕾雅推荐（最安全，与钱相关）
- **(c) 全量覆盖**：连手填价一起重写。⚠️ 会**永久覆盖人工维护的价格**，且没有回收站可退（只有价格表备份，不是记录级）。
> 你原话「主要用于批量更新目标记录的价格」听起来偏 (b)/(c)，但 (c) 风险高，**请你定**。

### P2 · 退舱行
`docs/mainsite/specs/退舱记录处理约定.md` 铁律 1/2 + §4：退舱行**不得作为批量操作的落点**。新功能是批量写 `单箱价格` → **必须排除退舱行**，且按"不得静默处理"要求**报出跳过了几条**。
> 请确认此口径（默认按此写）。

### P3 · 是否顺手补现有两处退舱缺口
实读发现 **`/api/price/batch`（`app.py:922-945`）与 `/api/price/recalc`（`admin_api.py:1109-1111`）都没有退舱守卫** —— 按铁律它们同样是"批量落点"，会改写退舱行的单价。§4 要求"动手前先问"。
- **(a)** 只登记，本轮不修（严格遵守"计划外问题只登记"）；
- **(b)** 一并修（三处统一加 `AND COALESCE("状态",'')<>'退舱'`）。
> 芙蕾雅倾向 **(b)**：同一个 bug 类，一次修干净；但按规矩必须你点头。

### P4 · 与现有「批量算价（所有未算价行）」的关系
新功能与 `priceall` 高度重叠（差别：新=当前筛选+可重算；旧=全库+只补空）。
- **(a)** 两个菜单项都保留；
- **(b)** 用新功能**替换**旧项（旧项是"全库"这种过宽范围，容易误伤）；
- **(c)** 保留旧项但改文案，明确"全库"。
> 芙蕾雅倾向 **(b)** 或 **(c)**。

### P5 · 排期位置
本功能与 **PR-B** 有实质依赖：PR-B② 会把 COC 无价的口径从"SOC 回落"改成"留空"，PR-B⑤ 给价格端点补审计。新功能若在 PR-B 之前做，重算用的还是**旧口径**，回头要返工。
- **(a)** 排在 PR-B **之后**（PR-E）； ← 芙蕾雅推荐
- **(b)** 插到前面单独做。

## 4. 拟定实现（拍板后定稿；先按 P1=(b)、P2=排除、P5=(a) 写）

### 4.1 后端 · 新端点 `POST /api/price/recalc_filtered`（`app.py`）
```
入参：{"ids": [int, ...], "mode": "machine|empty|all", "dry_run": bool}
1. ids 去重；长度上限保护（建议 > 5000 直接拒绝并提示"请先缩小筛选"）
2. 取行：SELECT ... FROM records WHERE id IN (...) AND COALESCE(is_deleted,0)=0
   - 命中 id 里的退舱行 → 计入 cancelled_skipped，**不参与算价、不写库**
3. 逐行 compute_price()（**共用**，口径随 PR-B② 生效；不另写一份）
4. 按 mode 决定是否覆盖；绝对值差 < 0.005 视为"无变化"，不写
5. 写入 updated_by = "筛选重算"
6. 审计：event="改价·筛选重算"，
   detail=f"ids={n} changed={c} unchanged={u} failed={f} cancelled_skipped={k} mode={mode} dry_run={bool}"
   （**只写一条 summary**，不逐行写，避免灌爆审计表）
返回：{"ok":true,"scanned":n,"changed":c,"unchanged":u,"failed":f,"cancelled_skipped":k,"preview":[...]}
```
- `dry_run=true` 时只统计不写库（供"影子期"用，见 §4.4）。

### 4.2 权限登记（`auth/rbac.py`）
新增：`("POST", "/api/price/recalc_filtered"): "price:manage"`（比照现有 `:112-113` 的 `/api/price/...` 两条）。
⚠️ strict 模式下**必须登记**，漏登记会被门禁按未登记路由拒绝。

### 4.3 前端（`templates/index.html` + `static/app.js`）
- 菜单加一项（放在 `price`/`priceall` 附近）：`<div class="ctx-item" data-act="priceflt">按当前筛选结果重新算价</div>`
- `ctxMenu` 点击分发（`static/app.js:2686-2688` 附近）加分支 → `recalcFiltered()`：
  1. `const rows = getView();`（= 当前筛选结果）
  2. 二次确认，文案带**行数**与**退舱提示**，例如：
     「将对**当前筛选的 N 行**重新算价（其中退舱 X 行会被跳过）。`<mode 说明>`。继续？」
  3. 先发 `dry_run=true` 拿"将改 M 行"，若 M 与预期不符可取消（影子期；见 §4.4）
  4. 实发 → 回报「已重算：改写 M 行，无变化 U 行，跳过退舱 X 行，算不出价 F 行」→ `loadRows().then(renderActive)`

### 4.4 影子期（按 `docs/meta/specs/2026-10-06-验收圣经-可长期复用.md`）
本功能属"判定类"改动 → 先 `dry_run` 观察（只报将改行数与明细），人工对答案一致后再落库。
