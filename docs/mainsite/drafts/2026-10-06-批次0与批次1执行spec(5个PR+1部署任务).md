# PR-1 · 退舱写路径加固

## 1.1 目标

让 `AGENTS.md` 与 `docs/退舱记录处理约定.md` 里的退舱铁律，**在所有写路径上真正生效**，同时**保证人工仍能用**。

## 1.2 现状（实读证据）

铁律目前**只在两处落地**：`import_excel.py:222-226`、`manifest_engine.py:463-468`。以下三条写路径**没有守卫**：

| 位置 | 现状 |
|---|---|
| `app.py:716-718` `api_delete_row` | `UPDATE records SET is_deleted=1 ... WHERE id=?` —— **只判 id，不看状态** |
| `app.py:783-788` `sync_departure` | 按 `班列号` 批量改发班时间，`WHERE` 只有 `is_deleted` 条件，**没有状态条件** ← **最容易无意触发** |
| `app.py:752` `api_trash_purge` | `DELETE ... WHERE id=? AND is_deleted=1` —— 不排除退舱 |

前端同样开放：`static/app.js:1632-1638`（右键删除无状态判断）、`static/app.js:874`（退舱行只加红底类，仍可编辑）。

## 1.3 改动要求（毛骁洋 2026-10-06 明确）

**规则**：退舱记录 ——

| 允许 | 不允许 |
|---|---|
| **复制**该行 | 删除（软删、彻底删除） |
| **修改「备注」** | 修改其他任何单元格 |
| 查看、筛选、导出 | 作为批量操作的落点 |

**后端**
1. `api_delete_row`：目标是退舱行 → **拒绝**，返回明确的 JSON 错误（含原因），**不得静默**。
2. `sync_departure`：`UPDATE` 的 `WHERE` **加上** `AND COALESCE("状态",'')<>'退舱'`。
   > 这是本次**唯一"必须改"**的一条——改发班时间是日常操作。
3. `api_trash_purge`：目标是退舱行 → **拒绝**，返回明确错误。

**前端**
4. 退舱行：**禁用**右键菜单里的「删除此行」；**禁用**除「备注」外的单元格编辑入口。
5. 退舱行：**保留**「复制」（右键/快捷键复制该行）。
6. 被拒绝时，**必须给用户可见提示**（toast 或行内提示），且措辞说明"这是退舱记录"。

> ⚠️ **不得"静默自动处理"**（毛骁洋原话）。任何涉及退舱的批量动作，要么排除它，要么明确报出来。

## 1.4 验收

1. **软删退舱行 → 被拒**（附请求与响应原文）。
2. **改一个班列的发班时间** → 同班列的**正常行被改**、**退舱行原值不变**（附改前后两条记录的实际字段值）。
3. **彻底删除退舱行 → 被拒**。
4. **前端**：退舱行能复制、能改备注；其他格子点不动；右键无「删除」项（各附一次人工核对结果）。
5. **回归**：`& $PY -m pytest -q -p no:cacheprovider` → `0 failed`。
6. **新增测试**：至少覆盖 §1.4 的第 1、2、3 条（用临时库）。

## 1.5 不在范围

- 不改 `load_records` 的过滤条件、不改舱单引擎的守卫（已有）。
- 不改 `import_excel.py` 的 J/K 守卫（已验收）。
- 不加"自动把退舱行隐藏"之类的行为。

# PR-2 · 抽 `static/auth.js` 统一请求层

## 2.1 目标（一个 PR 解决两件事）

1. **消除重复**：现在「怎么跟后台发请求」这段代码被抄了三份，且三份已经不完全一样。
2. **达成 G9 前置**：`manifest.html` **一份都没有** —— 它是四个页面里**唯一不带 CSRF 头**的。权限模块一翻 `=1`，`/api/manifest/*` 的全部 POST 会 **403**（见 `auth/README.md` §5）。

## 2.2 现状（实测）

| 页面 | 请求包装 | `X-CSRF-Token` |
|---|---|---|
| `static/app.js:12-28` | ✅ | ✅ |
| `templates/admin.html:262` | ✅ | ✅ |
| `templates/tuoshu.html:163` | ✅ | ✅ |
| `templates/manifest.html` | ❌ **无**（`:189-194` 是裸 `fetch`） | ❌ |

另外：`admin.html` / `tuoshu.html` / `manifest.html` **都缺登录弹窗**（只有 `templates/index.html:205` 有）—— 这是已登记缺陷 G3。

## 2.3 改动要求

1. 新建 **`static/auth.js`**，内容 = 现在 `static/app.js:12-28` 那套请求包装（同源时对非 GET 自动带 `X-CSRF-Token`、带 `credentials`），**外加**：收到 **401 时调用页面提供的 `showLoginModal()`**。
2. **登录弹窗的 DOM 不抽**：四个页面**各自**照 `templates/index.html:205` 的那段**复制一份**（避免动态注入 DOM 带来的风险）。`auth.js` 只负责"什么时候弹"。
3. 四个页面各加一行 `<script src="static/auth.js"></script>`，并把页面内**重复的包装删掉**，改为使用它。
4. `static/app.js` 也改为使用 `auth.js`，删除自己的那份重复实现（注意保持原有行为不变）。
5. **不改任何接口路径、参数、返回结构**；**不引入框架、不引入构建工具、不加 npm**。

## 2.4 验收

1. **四页逐页人工核对**（这是本 PR 的主要验收方式，因为前端没有自动化测试）：
   主表 / 舱单 / 托书 / 管理 —— 每页把平时会用的功能点一遍，**行为与改造前完全一致**。
2. **未登录时打开四页中的任意一页 → 都能弹出登录框并登录成功**（每页各附一次证据）。
3. **登录后打开舱单页 → 上传/应用/回退的请求确实带上了 `X-CSRF-Token`**（附请求头证据）。
4. `grep` 证明**没有任何页面**再自带重复的请求包装实现。
5. 回归：现有测试 `0 failed`。

## 2.5 风险与禁令

- ⚠️ 本 PR **是批次 0 里唯一需要人工逐页验证的一项**（它动三个已经在正常工作的页面）。

# PR-3 · 每日自动备份 `yxo.db`

## 4.1 目标

让**任何误改都能回到"今天早上"**。

## 4.2 现状（为什么要做）

- **回滚脚本不回滚数据库**（`AGENTS.md` §9.5：`scripts/rollback.ps1` 只回滚代码）。
- 现有的数据库快照**只在舱单导入时**产生（`app.py:352-363`）。
- 软删有回收站兜底，但**单元格被覆盖就完全无痕**。
- 生产库是**唯一真源**。

## 4.3 改动要求

1. **定时备份**：每日至少一次（建议每天固定时间），备份 `yxo.db`。
   - 用 SQLite 的备份 API 或先 `PRAGMA wal_checkpoint(FULL)` 再复制（参考 `manifest_engine.py:740-747` 的现成写法）。
   - 备份文件命名带日期，例如 `backup/yxo_YYYYMMDD.db`。
2. **保留策略**：保留最近 N 份（**N 由毛骁洋定**，建议 14–30），超出的自动清理。
3. **备份位置**：**必须放本地盘**，不要放 SMB/UNC（历史上 SMB 写会报 `readonly database`）。
4. **启动迁移前也备份一次**（`init_db`/`migrate_db` 之前）。
5. **可发现**：主站页面上显示"**最近一次备份时间**"，让人一眼知道它在工作。

## 4.4 验收（**必须包含一次真实的恢复演练**）

1. 手动触发一次备份 → 文件生成，大小合理（附 `dir` 输出）。
2. **恢复演练**：挑一份备份 → 在**非生产副本**上真的恢复一次 → 核对关键数据（如 `records` 行数、某条记录的字段值）与备份时一致。**附完整命令与核对结果。**
3. 保留策略生效：造几份多余备份 → 跑清理 → 只剩 N 份。
4. 页面上能看到"最近一次备份时间"。
5. ⚠️ **只给备份脚本不算完成** —— 第 2 条不通过，本 PR 不算完成。

## 4.5 需要毛骁洋定

- 保留几份？
- 每天几点跑？
- 备份目录放哪（建议在生产机的本地盘，如 `D:\YXO_DATA\备份\`；注意 `manifest_engine.py:29` 已有 `BACKUP_DIR` 常量，可复用）。
