## 一、现状（怎么运转的，已核实行号）

月份筛选是**纯前端本地过滤**，不涉及后端：

1. 数据是一次性全量拉取（`loadRows()` → `api/rows`，app.js:1577，后端无任何月份参数）。
2. 月份按钮条 `renderMonthTabs()`（app.js:568-602）：月份列表由 `monthsFromData()`（app.js:562-566）对当前数据逐条调 `monthOf()` 归月去重生成，降序排列；跨年时自动出年份下拉。
3. **归月函数 `monthOf()`（app.js:532-539）就是本次要改的核心**——现状是：优先取 `台账月份`（匹配 `YYYY-MM`），为空才回退 `发班时间` 前 7 位。
4. 点按钮只改 `STATE.month` 本地重渲染（app.js:604-610），过滤发生在 `passFilter()`（app.js:620 行：`monthOf(r) !== STATE.month` 则排除）。

**`passFilter` / `monthOf` 的三个消费方**（改一处函数全部自动跟随，无需分别改）：

| 消费方 | 位置 | 说明 |

| 统计页 | app.js:1156 | **统计页"按月"分组本来就用 `发班时间`**（app.js:1165-1176）——改完后筛选口径与统计口径终于一致 |
| 导出 | app.js:1515-1519 | 导出的是 `DATA.filter(passFilter)` 的行 |

## 二、目标逻辑

`monthOf()` 改为**只看 `发班时间` 的月份**：

```js
function monthOf(r) {
  // 月份筛选口径（2026-10-15 洋定）：按班列发运时间（发班时间）归月。
  // 「台账月份」退为数据统计辅助字段，不再参与月份筛选。
  const s = String(r["发班时间"] || "").trim();
  const m = s.slice(0, 7).replace(/\//g, "-");
  return /^\d{4}-\d{2}$/.test(m) ? m : "";
}
```

改动就这一处函数体（保留原函数名与调用点，5 个调用方零改动）。`replace(/\//g,"-")` 保留，兼容历史可能存在的 `2026/10/01` 斜杠格式。

## 四、行为变化（改完后用户会感知到的）

1. **手动改过 `台账月份` 归属的记录**（该字段的用途就是"默认随发班时间，可手动改"，config.py:50）：月份按钮筛选不再跟随手动归属，回到发班时间所在月。**这正是本次改动的目的**，但意味着之前靠手动归月来"挪月份"的记录会"挪回去"——若生产上有同事依赖此玩法，需要知情。
2. 月份按钮条上出现的月份集合 = 数据里 `发班时间` 出现过的月份（原来 = `台账月份` 的月份集合，两者绝大多数情况重合）。
3. 导出、统计随 `passFilter` 自动跟随，无额外动作。

## 五、拍板记录（2026-10-16 洋已定，两点的分析过程留档）

### 拍板 1（已定：方案 A）：`发班时间` 为空的记录只在「全部」下可见

库中 `发班时间`、`台账月份` 都允许为空（app.py:216 有空值兜底）。按方案 A 实现，`发班时间` 为空的记录 `monthOf` 返回 `""`——**不归入任何月份按钮，只在「全部」下可见**。

- 方案 A 定案理由：筛选口径单一，没有隐藏回退；若回退 `台账月份`（原方案 B），同一条记录的月份归属会在两个口径间漂移（筛选看发班时间、回退看台账月份），数据对账时更乱。且本次初衷就是"筛选口径与统计口径统一"（统计页按发班时间分组、空值落 `(空)` 桶）——筛选侧回退台账月份会让表格和统计立刻回到两套口径，恰与初衷相反。**A 是唯一让表格/统计/导出三个消费方口径自洽的方案。**
- 落码前 count 一次空值量级，用途只是**向洋汇报影响面**（"有多少条记录只在「全部」下可见"），不改变口径。

### 空发班时间在统计页与导出的连带口径（一并写清，避免"数据对不上"的错觉）

| 场景 | 现状行为（已核代码，无需改） | 用户感知 |
|---|---|---|
| 统计页"按月(发班时间)"分组 | 空 `发班时间` 落 **`(空)` 桶**（app.js:1165 `|| "(空)"`） | 统计页始终有 `(空)` 一行，不会凭空消失，与表格「全部」下的行数对得上 |
| 月份筛选下的统计 | 选中某月 → 统计基于 `passFilter` 结果，空值记录不参与 | 正常 |
| 导出 | 导出跟随 `passFilter`：空值记录**只有切到「全部」才导出得到** | ⚠️ 要写进 UI 预期：用户若在选中某月时发现"导出的行数 < 库里该客户总行数"，先检查是否有空发班时间的记录（可用搜索定位） |

### 拍板 2（已定）：字段口径确认 = `发班时间`

洋 2026-10-16 确认："班列发运时间"即库字段 **`发班时间`**（`YYYY-MM-DD`，舱单导入时由 manifest_engine 统一归一为该格式），按其实施。

**已全库核实（2026-10-15）**：`records` 表只有 `发班时间` 一个发运类字段。其他相近名字都不是它、不冲突：`发车时间/发运日期` 等是舱单导入时 Excel 表头**别名**（manifest_engine.py:191-192 映射进 `发班时间`，落库只有一个字段）；`tuoshu_engine.py:82` 的"发运日期"是托书模板单元格注释；`tracing_xls.py` 的"发车时间"是运踪文件域，与 records 无关。OpenCode 落码时再 grep 一遍读写点复核即可（一条命令的事）。

## 六、验收要点（转任务书时带走）

1. 选中某月 → 表格只显示该月 `发班时间` 的记录；手动把某条 `台账月份` 改成别的月份，**筛选不跟随**（核心验收）。
2. 统计页在选中月份下的数字 = 表格可见行集合（口径一致性）。
3. 导出当月 = 表格当月所见。
4. `发班时间` 为空的记录：按**方案 A** 验证——只在「全部」出现，任何月份按钮下都不出现。**并确认月份条上不出现空月份按钮**——`monthsFromData()` 已有 `if (m)` 过滤（app.js:564），空串理论上进不了集合，此条属"确认既有防线在改后仍生效"。
5. 月份条跨年年份下拉逻辑不变；`pickDefaultMonth`（app.js:640）**代码逻辑不变（仍取数据中最大月），但因归月口径变化，默认落在的月份可能与改前不同**（例：某记录 `台账月份=2026-09` 但 `发班时间=2026-08`，改前默认可能落 09、改后落 08）。这是预期效果，不是 bug。
6. 影子期回归：游客/影子身份下月份条正常，无弹窗、无 403。
