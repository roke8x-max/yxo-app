## PR-A · `sync_departure`（改发班时间批量联动）必须排除退舱行

### 为什么
`AGENTS.md` 硬规则 12 与 `docs/mainsite/specs/退舱记录处理约定.md` 规定：**退舱记录不得作为批量操作的落点**（人工手动单条删除除外）。改发班时间是**按班列批量**操作，现在会把同班列的退舱行一起改掉——这是日常操作，最容易无意触发。

### 现状（实读）
`app.py` `sync_departure` 的 UPDATE `WHERE` 目前是：
```sql
WHERE "班列号"=? AND id<>? AND COALESCE(is_deleted,0)=0
  AND "发班时间"<>? AND (substr("发班时间",1,4)=? OR "发班时间" IS NULL OR "发班时间"='')
```
**没有状态条件。**

### 改动
在 `WHERE` 中追加：`AND COALESCE("状态",'')<>'退舱'`
（一行改动；**不要**动其它任何逻辑，尤其年份锁定与 `old_year` 语义。）

### 验收
1. 构造同一班列「1 条正常 + 1 条退舱」，正常行有发班时间、退舱行有另一时间；
2. 改正常行的发班时间（PATCH `/api/row/<id>`）→ 断言：**正常行被联动改、退舱行原值不变**；
3. 退舱行可**人工手动单条删除**不受影响（符合"人能删，系统不替人删"）。

## PR-B · 价格维护加固（5 项）

### 为什么
价格表（`price_config.json`）是自动算价的唯一来源，目前有 5 个"改错了恢复不了 / 算错没人知道"的毛病，均已拍板要修。

### 改动（逐项）

| # | 改动 | 位置 | 依据 |
|---|---|---|---|
| ① | **读价格文件失败 → 报错**，不再静默返回空配置 | `admin_api.py` `_load_price_cfg()`（现 `except: return {"prices":{},"exrates":{}}`） | 现状最险：读失败→页面显示无价→此时保存会**把整个价格文件覆盖成只剩一条** |
| ② | **COC 无价时不回落 SOC 价 → 留空** | ⚠️ **两处都要改**：`app.py` 的 `compute_price` 与 `admin_api.py` 的算价实现 | 两处实现独立（历史遗留），口径必须同步，否则同一单在不同入口算出不同的价 |
| ③ | **提示要分开**：配置读失败 / 真的无匹配价，给不同提示 | `app.py` 算价返回处 | 现在两种情况同一句 msg |
| ④ | 备份加**保留上限**；界面加「**从备份恢复**」入口 | `admin_api.py`（已有 `price_backups/` 写前备份，但无保留策略、无恢复入口） | — |
| ⑤ | **价格端点补审计**（谁·何时·把哪个值改成什么） | `admin_api.py` 价格相关端点 | 现状：**零 audit 调用**；参照 `app.py` 已有的 `_audit.log_event` 写法 |

### 验收
1. 把 `price_config.json` 临时改名 → 打开价格页 → 看到明确"读取失败"错误（**不是**"没有价格"），且保存被拒绝或强提示；
2. 造一条只有 SOC 价、无 COC 价的规则 → 对 COC 箱算价 → **单价留空**（不回落到 SOC 价），有可见提示；
3. 触发"真的无匹配价" → 提示与第 1 条**明显不同**；
4. 造 N+1 份备份 → 跑清理 → 只剩 N 份；
5. 从「从备份恢复」入口恢复一次 → 内容回到备份时点；
6. 改一次价格 → 审计表能查到"谁、何时、旧值→新值"；
7. 回归：`0 failed`。

## PR-C · 停用 Excel 台账导入

### 为什么（已拍板）
`/api/import` 是最早的数据导入设计，后来发现舱单列表就抛弃了；历史数据已全部入库，新的也没有 WPS 在线表台账了。而且它走 `config.IMPORT_FILE`（硬编码 `八月记录汇总.xlsx`），任何有写权限的人误触会把 8 月基础字段刷回今天。

### 改动
1. 删除路由 **`POST /api/import`**、**`POST /api/import_upload`**（`app.py`）以及 `auth/rbac.py` 里对应的两条登记；
2. 删除前端入口（主表页「导入 Excel」按钮及 `app.js` 里 `fetch("api/import_upload"...)` 那段）；
3. 删除 `config.IMPORT_FILE`（`config.py`）；
4. ⚠️ **`import_excel.py` 保留、标注停用**：它含**已验收的退舱守卫**（`import_excel.py:222-226`）且有测试在跑。文件头加醒目注释"已停用（2026-10-12），`/api/import` 已删除；保留作为退舱守卫参考实现"。**彻底删除需毛骁洋单独确认。**

### 验收
1. `grep` 证明 `/api/import`、`/api/import_upload`、`IMPORT_FILE` 全仓无引用（除已停用的 `import_excel.py` 自身）；
2. 主表页找不到「导入 Excel」入口；
3. 直接请求这两个路径 → **404**；
4. 回归：`0 failed`（保留的 `test_import_excel_guards.py` 应仍为绿）。

## PR-D · 只渲染当前视图（查看体验 · 用户明确"非常重要"）

### 为什么
页面有表格 / 看板 / 统计等多块视图，现在 `renderAll()` **无条件全部重建**（含隐藏的看板也把全部记录造成卡片），"刷新 / 导入 / 删除"都走它。用户 2026-10-12 复述："**我就是发现现在有点慢**"。这是主站核心价值（一站式查看）的直接瓶颈。

### 改动
`static/app.js`：只渲染**用户当前在看的视图**；看板没打开就不造卡片；切换视图时才渲染对应块。
- **不引框架、不加构建**（"改完刷新即生效"是被珍视的性质）。
- **不改变任何功能行为**，只改"什么时候干活"。

### 验收
1. 打开主表（默认表格视图），**看板未打开** → 请求/渲染数量显著下降（附前后对比：DevTools 或手动计时）；
2. 切到看板 → 正常渲染；
3. 四个视图逐一人工核对，行为与改造前一致。

## 共同硬约束（四件都适用）

1. **禁止 `commit` / `push` / 开 PR** —— 落码后停下报告，由毛骁洋执行 git。
2. 用 `git add <具体文件>`，**禁止 `git add -A`**；分支名**扁平、不带斜杠**，从 `main` 拉。
3. **一次 PR 只做一件事。**
4. 报告必须附实跑证据：命令 + 输出末几行 + `文件:行号`。禁止「已证实」「应该没问题」。
5. **不得为了让测试变绿而放宽任何业务判据**；测试红先定性（数据/环境/逻辑）。
6. 测试不得连生产库；用临时库。
7. 发现计划外问题**只登记，不顺手修**。
8. 与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准并立即报告。
9. **验收方式照 `docs/meta/specs/2026-10-06-验收圣经-可长期复用.md`**：凡涉及"判定"的改动，先走影子期（只观察不落库），再人工对答案。
