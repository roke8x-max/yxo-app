## 一、目标规则（一张表）

退舱行（`TRIM(状态)=='退舱'`）：

| 字段 | 单格改（`PATCH /api/row/<id>`） | 批量改（`POST /api/cells` / 按班列 / 批量算价） |
|---|---|---|
| **备注** | ✅ 允许（原有规则） | ✅ **允许**（洋 2026-10-19 17:12 拍板） |
| **状态** | ✅ 允许（本次新增放宽） | ⛔ **排除**（洋原话：「只要不被**批量**修改就行」） |
| 其余全部字段（箱号/封号/客户编码/发班时间/目的站/价格…） | ⛔ 拒绝 | ⛔ 排除（不变） |

**两条易混的边界，必须分开写死：**

1. **「批量排除退舱行」有且只有一个例外：备注。** 工单 §1「批量操作不退让」保留，但备注这一列按洋本次拍板豁免。
   其余列（含状态）在批量路径上仍**一个都不许落**。
2. **状态只放开「单格人工改」**：`sync_departure`（按班列改发班时间）、`/api/price/batch`、`/api/admin/price/recalc`
   的退舱守卫**一律保持**，本次不得改动。

⇒ 因此后端需要**两个**白名单常量（不是一个小叽工单里那个共用的）：

| 常量 | 值 | 用在哪 |
|---|---|---|
| `CANCEL_EDITABLE_FIELDS` | `("备注", "状态")` | 单格 `api_update()` |
| `CANCEL_BATCH_EDITABLE_FIELDS` | `("备注",)` | 批量 `api_cells()` |

> ⚠️ 这是对工单原片段的一处**必要修正**：工单给的 `CANCEL_EDITABLE = ("备注", "状态")` 同时塞进两个端点，
> 等于把「状态」也放进了批量路径 —— 与洋「状态不被批量改」直接冲突。

### 2.3 写路径覆盖面（工单只点了两条端点，实际 UI 入口有 8 个，汇到三条端点）

| UI 入口 | 前端函数 | 走的端点 | 失败时的现状 |
|---|---|---|---|
| 双击/键入改一格 | `saveCell()` `app.js:1234` | PATCH | 只 toast「保存失败」，**界面仍显示被拒的新值**（`app.js:1265`） |

| 多行/多列批量粘贴（右键 `app.js:1778`、单元格 Ctrl+V / 全局 `paste` 事件 `app.js:2714`） | `doGridPaste()` `app.js:1859` → `applyEdits()` `app.js:1752` | **本地 DATA 先乐观更新**（`app.js:1754`、`app.js:1886`），服务端若静默跳过 → 屏幕与库里不一致 |
| 整行粘贴 | `applyEdits()` 同上 | POST /api/cells | 同上 |
| 撤销（单格） | `undo()` `app.js:2029` | PATCH | 同 1 |
| 撤销（批量粘贴） | `undo()` `app.js:2014` | POST /api/cells | 同上 |
| 专列批量设置条 | `applyBulkSet()` `app.js:2410` | POST /api/cells | 提示语用的是**本地 `edits.length`**（`app.js:2435`），不是服务端 `saved` → 会虚报行数 |

## 三、后端改动（两处 + 一个共用常量）

### 3.1 新增模块级常量与判定函数（唯一真源）

放在 `app.py` 现有 `DATE_FIELDS`（`app.py:1030`）附近，或紧邻 `api_update` 之前，**只定义一处**：

```python
# 退舱行「单格人工编辑」白名单（毛骁洋 2026-10-19 拍板）：
# 状态可人工改（只要不被批量改），备注沿用 §4 原有规则，其余字段防误改。
# 依据 AGENTS.md 硬规则 12 + docs/mainsite/specs/退舱记录处理约定.md §4
CANCEL_EDITABLE_FIELDS = ("备注", "状态")
# 退舱行「批量落点」白名单（洋 2026-10-19 17:12：批量改备注允许）：
# 只有备注；状态只在单格路径放开，批量路径必须排除。
CANCEL_BATCH_EDITABLE_FIELDS = ("备注",)


def _is_cancel_row(conn, rid):
    """该行当前是否为退舱记录（状态为 NULL / 空串一律视为非退舱）。"""
    r = conn.execute('SELECT COALESCE("状态",\'\') AS s FROM records WHERE id=?',
                     (rid,)).fetchone()
    return bool(r and str(r["s"]).strip() == "退舱")
```

> ⚠️ 判定必须 `str(...).strip() == "退舱"`，与 `app.py:952`（PR#36）、`app.py:783`（PR#34）口径一致。
> ⚠️ 不要另开连接：工单片段在 `get_db()` 之前单开一次再关，多一次 IO 且早退路径容易漏 `close()`。统一用后面已有的 `conn`。

### 3.2 `api_update()`（`app.py:790`）

在 `if field not in config.ALL_FIELDS`（400）**之后**、任何 `UPDATE` **之前**：

```python
    conn = get_db()
    if field not in CANCEL_EDITABLE_FIELDS and _is_cancel_row(conn, rid):
        conn.close()          # 早退必须关连接，否则每次被拒都泄漏一个句柄
        return jsonify({"ok": False, "msg": "退舱记录只允许修改「备注」和「状态」"}), 403
```

要点：
- **顺序**：非法字段仍是 400；只有合法字段才走退舱判断（否则报错信息会互相掩盖）。
- **不存在的 rid 保持原行为**（`_is_cancel_row` 返回 `False` → 落到原 `UPDATE` 影响 0 行 → 仍返回 `ok:True`）。本次不修这个既有语义。
- `发班时间` 被拒后**不会有联动**（判断在 `sync_departure` 之前），`synced` 语义不受影响。

### 3.3 `api_cells()`（`app.py:816`）

`for e in edits:` 循环内、`field not in config.ALL_FIELDS or not isinstance(rid, int)` 判断**之后**、`departure_year()` **之前**：

```python
    saved = 0
    cancelled_skipped = 0          # 被跳过的退舱单元格数，必须报出来（§4「不得静默处理」）
    ...
        if field not in CANCEL_BATCH_EDITABLE_FIELDS and _is_cancel_row(conn, rid):
            cancelled_skipped += 1
            continue
```

> 注意这里用的是 **`CANCEL_BATCH_EDITABLE_FIELDS`（只有备注）**，不是单格那个。
> 结果：`/api/cells` 批量改退舱行**备注 → 写入**；批量改退舱行**状态 → 跳过并计数**。

返回体（保留 `ok`/`saved`，新增一个键，**不改既有键语义**）：

```python

```

- 命名用 **`cancelled_skipped`**，与 PR#36 的 `/api/price/batch`（`app.py:973`）保持一致；工单里的 `skipped_cancel` 不采用（同一概念两个名字，后续维护会找错）。
- 计数点：**在 `continue` 之前 +1**，与「未写入」严格一一对应（对齐 R4 计数点约定）。
- 性能：批发 900 条时最多多 900 次主键点查（本地 SQLite，毫秒级），不预先批量查——保持代码简单。

## 四、前端改动（**必做**，不是可选项）

洋的原话是「不要被随意**不小心**改掉了」。只做后端，用户得点进去、输完、失去焦点才被拒，还会看到一屏假值——达不到「防不小心」的目的。工作量很小：

### 4.1 三个小 helper（放在 `app.js:877` 附近）

```js
const CANCEL_EDITABLE = ["备注", "状态"];        // 对齐后端 CANCEL_EDITABLE_FIELDS（单格）
const CANCEL_BATCH_EDITABLE = ["备注"];          // 对齐后端 CANCEL_BATCH_EDITABLE_FIELDS（批量）
function isCancelRow(r) { return String(r["状态"] || "").trim() === "退舱"; }
// 单格：备注/状态 可改，其余锁
function isCancelLocked(r, field) { return isCancelRow(r) && CANCEL_EDITABLE.indexOf(field) < 0; }
// 批量：只有备注可写，状态与其他一律跳过
function isCancelBatchLocked(r, field) { return isCancelRow(r) && CANCEL_BATCH_EDITABLE.indexOf(field) < 0; }
```

**别把这两个 helper 合成一个** —— `isCancelLocked` 对「状态」返回 false（单格该放），
批量路径上必须用 `isCancelBatchLocked` 才会跳过状态。

顺手把 `app.js:877` 的 `if (String(r["状态"] || "").trim() === "退舱")` 换成 `if (isCancelRow(r))`（纯等价替换，避免两套判据漂移）。

### 4.2 打开编辑器就拦住（体验层，主防线）

`openCellEditor()`（`app.js:202`）**第一行**：

```js
  if (isCancelLocked(r, c.name)) { toast("退舱记录只允许修改「备注」和「状态」"); return; }
```

覆盖双击与键入两条入口，用户根本进不了编辑态。

### 4.3 `saveCell()` 兜底 + **失败回滚**（必做）

`saveCell()`（`app.js:1234`）开头：

```js
  if (isCancelLocked(rec, field)) { toast("退舱记录只允许修改「备注」和「状态」"); return; }
```
（`rec` 已在函数内取到；注意 `rec` 可能为 undefined，判空后再判）

同时修正失败分支（`app.js:1265`）——当前只 toast，**界面留着被拒的值**：

```js
    } else {
      clearPending(id, field);
      if (rec) rec[field] = oldValue;   // DATA 本来就没改，重绘即可还原显示
      renderActive();
      toast("保存失败: " + j.msg);
    }
```

并把 `pushUndo(...)`（`app.js:1237`）**移到成功分支**——否则每次被拒都会留一条永远无法正确回放的撤销记录（且 `renderActive()` 前就压栈，撤销栈会指向一个没发生的操作）。

### 4.4 批量的三个调用方：别再「乐观更新完就当成功」

**接口先定死**（否则两处各自计数串不起来）：`applyEdits(edits, msg, extraCancelSkipped = 0)`

| 函数 | 改法 |
|---|---|
| `applyEdits()` `app.js:1752` | 加第 3 个形参 `extraCancelSkipped = 0`（默认 0 ⇒ 整行粘贴那条调用不受影响）。进来先按 `isCancelBatchLocked(DATA.find(x => x.id === e.id), e.field)` 过滤 `edits`（`edits` 只有 `{id, field, value}`，**拿不到 row 必须自己查**），自身计数 `selfSkipped`（`let selfSkipped = 0` 放过滤循环**之前**）；**跳过数分两段拼**：请求前 `skippedNoReq = extraCancelSkipped + selfSkipped`，`.then((j) => ...)` 里 `totalSkipped = skippedNoReq + (j.cancelled_skipped \|\| 0)` |
| `doGridPaste()` `app.js:1885-1886` | 在 `edits.push(...)` 与 `target[tc.name] = nv` **之前** `if (isCancelBatchLocked(target, tc.name)) { skippedCancel++; continue; }`；`skippedCancel` 是**它自己的局部变量**，靠第 3 个参数传给 `applyEdits`（否则 `applyEdits` 根本拿不到） |
| `applyBulkSet()` `app.js:2410` | **直接 `fetch("api/cells")`，不走 `applyEdits`** ⇒ 不会双重 toast，也**不要**改成调 `applyEdits`。`let skipped = 0;` 与 `const edits = []` 一起初始化；`targets.forEach` 内按 `isCancelBatchLocked(r, field)` 跳过并计数。**空 `edits` 时不发请求、提示按原因分开**（`skipped > 0` → 「已跳过 N 个单元格」；否则原「没有需要补写的空值行」），该分支**不许引用 `j`** |

**过滤后 `kept` 为空**：不发空 POST，但**不许裸 return** —— `skippedNoReq > 0` 时 toast「退舱记录不可修改，已跳过 N 个单元格」并 `loadRows(true).then(renderActive)`（以服务端真值重取，防本地 `DATA` 漂移）；`skippedNoReq === 0` 才沿用原提示「没有需要粘贴的内容」。

> ⚠️ **`j` 只在 `.then` 回调作用域里存在**。「全被跳过」这条路径**根本没发请求、没有 `j`**，
> 若把 `j.cancelled_skipped` 写进请求前的表达式，会直接 `ReferenceError`（不是 undefined）。
> 所以必须是「请求前 `skippedNoReq` + 回调内 `j.cancelled_skipped`」两段拼。任务书 §3.4.1 / §3.4.2 给了完整骨架。
> **`applyBulkSet` 的空 `edits` 分支踩的是同一个坑**（验收第 14 条正好走这条：3 条退舱行全被跳过）。

原则：**本地 DATA 的乐观更新只能对「确定会写成功」的格子做**；否则一律以服务端回包为准重取。
备注是例外（批量允许），所以它不会被过滤 —— 这是本次拍板的结果，不是漏判。

> ℹ️ `doBulkPaste()`（`app.js:1818`）是**死代码**：全仓（含 `templates/`）无任何调用点。
> 本次**不改也不删**，别因为"看起来漏了一条批量粘贴"就去动它。

### 4.5 静态资源版本号（容易漏）

### 4.6 修一处笔误（R7，洋 2026-10-19 一并做）

`openCellEditor()` 内重绘时算价按钮的判据写成了 `c.name === "备注"`（`app.js:210`），与列表重绘的 `"单箱价格"`（`app.js:942`）不一致。

⚠️ 这是**影响所有行**的顺手修 bug（不只退舱行），PR 描述里要单独写一条，别混进"本次新增守卫"里。
