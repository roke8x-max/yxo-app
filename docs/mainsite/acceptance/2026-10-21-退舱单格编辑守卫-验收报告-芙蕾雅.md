## 四、问题清单

### 🔴 P1（必须修）：退舱行「右键单格粘贴」会假成功、并在屏幕上留下脏值

`pasteToRow()` 单格分支（`app.js:1825-1828`）先写本地再调 `saveCell`：

```js
rec[target.name] = nv;
saveCell(id, target.name, nv);   // ← 现在会被 saveCell 的守卫直接 return
renderActive();
toast("已粘贴到「" + target.name + "」");
```

后果（我已用 VM 复现）：本地 `DATA` 变脏、界面显示新值、还提示"已粘贴到「箱号」"，**服务端一个字没写**，刷新就打回原形。
这正是 spec §2.3 要消灭的"屏幕假值"——而且**是本次新增的**（改之前 `saveCell` 不拦，粘贴能真写进去）。

**修法**（1 行，放在 `const target = ...; if (!target) return;` 之后）：

```js
    if (isCancelLocked(rec, target.name)) { toast("退舱记录只允许修改「备注」和「状态」"); return; }
```

> ✅ **已修（2026-10-22）**：落点 `static/app.js:1820`（在"内容相同"判断与 `rec[target.name] = nv` **之前**，位置正确）。
> 我复验（VM 实跑）：
> `pasteToRow(退舱,箱号)` → 本地 `箱号` 仍是 `BOX-C`（**未写脏**）、**0 次请求**、**只有一条**拦截 toast、**无**「已粘贴到…」；
> 对照 `pasteToRow(正常,箱号)` → 正常写入 + 提示「已粘贴到「箱号」」。

#### 补充：8 个写入口全扫过，`pasteToRow` 是**唯一**假成功入口（2026-10-22 复核）

判据：「是否先写本地 `DATA`、后被守卫拦下」。逐条核过代码：

| 入口 | 本地写入时机 | 被拦后果 | 判定 |
|---|---|---|---|
| `pasteToRow()` 单格 | 先 `rec[target.name] = nv` 再 `saveCell` | `DATA` 脏 + 假 toast | 🔴 **P1，唯一假成功** |
| `pasteToRow()` 整行 | 只拼 `edits`，交给 `applyEdits` 过滤 | 不写 | ✅ |
| `doGridPaste()` | `target[tc.name] = nv` 与 `edits.push` 同一 if 块，**过滤在其之前** | 两者都不执行，`DATA` 不脏 | 🟠 只有 P2 提示问题 |
| `applyEdits()` | 过滤后才 `kept.forEach` 写 `DATA` | 被过滤的不写 | ✅ |
| `applyBulkSet()` | 生成 `edits` 时跳过，不发请求 | 不写 | ✅ |
| `saveCell()` | 拦截时直接 `return`，不写 `DATA` | 不脏 | ✅ |
| `undo()` 单格 | **不走 `saveCell`**，直接 `fetch PATCH`，`j.ok` 才写 `DATA`（`app.js:2065-2074`） | 403 → `DATA` 不动 + toast「撤销失败: …」 | ✅ 无假成功；对被拦行撤销"点不动"（`undo()` 本来就不处理失败态）→ **既有行为，登记不修** |
| `undo()` 批量 | 走 `applyEdits`，被过滤不写 | 不写 | ✅（R1 的"清空字段"是既有 bug，另算） |
| `flushPending()` | `keepalive fetch`，无 UI | 静默 | spec 已接受 |

> 两处易混的定性差别，**别并成一条**：P1 是「脏数据 + 假话」，P2 只是「被拦了却说没内容」，`doGridPaste` **不会**写脏 `DATA`。

> 📌 **复验时别把下面这条当新问题**：对被退舱守卫拦下的行点「撤销」→ 会弹「撤销失败: 退舱记录只允许修改「备注」和「状态」」、`DATA` 不动。
> 这是 `undo()` 单格**本来就不处理失败态**的既有行为（与 R1 同族），不属本次引入，**登记不修**。

### 🟠 P2（必须修）：`doGridPaste` 全部被跳过时，提示把跳过数丢了

`app.js:1924` 仍是无条件早退：

```js
if (!edits.length) { toast("没有需要粘贴的内容"); return; }
```

VM 实测：对退舱行粘贴「箱号」→ toast 是「没有需要粘贴的内容」，而**实际是被拦了 1 个**（`skippedCancel=1` 已算出但没用上）。改前这里本来不会有"被拦"的情况，所以也是本次引入的误导。

**修法**：与 `applyBulkSet` 一致 ——

```js
  if (!edits.length) {
    if (skippedCancel > 0) toast("退舱记录不可修改，已跳过 " + skippedCancel + " 个单元格");
    else toast("没有需要粘贴的内容");
    return;
  }
```

> ✅ **已修（2026-10-22）**：落点 `static/app.js:1925-1929`。
> 我复验（VM 实跑）：`doGridPaste(退舱行, "箱号", "HACK")` → toast「退舱记录不可修改，已跳过 1 个单元格」、**0 次请求**。
> 混合场景（正常行 + 退舱行一起铺）此前已验：只提交正常行那条，toast 带「已跳过 1 个退舱单元格」。
