## 一、必须先测这个（决定整套方案成不成）

新方案把关联键压在 **`X-YXO-Forward-Id` 信头** 上：我们在转发邮件里塞一个隐藏信头，退信时指望对方把原信（含该信头）回传。

**这个信头到底能不能活着回来，代码层面无法验证，只能实测。** 它是新方案的命门：

- 能回来 → 主键可用，方案成立；
- 回不来 → 主键失效，只能靠"次键"（按失败收件人 + 发信账号反查）兜底，可靠性下降，需要我另做权衡。

**好消息：这个测试完全不需要新邮箱、不需要数科部** —— 用现有同事账号就能跑，退信会落在发信账号自己的收件箱。

---

## 二、跑这个脚本

存成 `ndr_key_probe.py` → **⚠️ 把标"改成真值"的行替换掉**（别原样复制）→ `python ndr_key_probe.py`

```python
# -*- coding: utf-8 -*-
"""四邮箱方案：验证 X-YXO-Forward-Id 能否随退信回到发信账号收件箱。"""
import imaplib, smtplib, ssl, time, uuid
from email.mime.text import MIMEText
from email import message_from_bytes

# ==================== ⚠️ 改成真值 ====================
SMTP_HOST = "smtp.qiye.aliyun.com"      # 以邮箱后台"客户端设置"为准
SMTP_PORT = 465
IMAP_HOST = "imap.qiye.aliyun.com"      # 以邮箱后台为准
IMAP_PORT = 993
SENDER_ACCOUNT  = "maoxiaoyang@cqtransit.com"     # 发信同事账号
SENDER_PASSWORD = "改成该账号的密码或客户端授权码"
BAD_RECIPIENT   = "no-such-user-abc123@cqtransit.com"   # 故意不存在的收件人
WAIT_SECONDS    = 150
# ======================================================

FID = f"{uuid.uuid4().hex[:16]}-{uuid.uuid4().hex[:8]}"   # 模拟 forward_id
TAG = uuid.uuid4().hex[:6]
print("本次 forward_id =", FID)


def send_probe():
    msg = MIMEText("probe body", "plain", "utf-8")
    msg["Subject"] = f"NDR KEY PROBE {TAG}"
    msg["From"] = SENDER_ACCOUNT
    msg["To"] = BAD_RECIPIENT
    msg["X-YXO-Forward-Id"] = FID          # ← 被测信头（与真实转发一致）
    with smtplib.SMTP_SSL(SMTP_HOST, SMTP_PORT,
                          context=ssl.create_default_context(), timeout=30) as s:
        s.login(SENDER_ACCOUNT, SENDER_PASSWORD)
        refused = s.sendmail(SENDER_ACCOUNT, [BAD_RECIPIENT], msg.as_string())
    print("[1] 发信完成，envelope=发信账号本人；refused =", refused)


def scan_inbox():
    print(f"[2] 等 {WAIT_SECONDS}s 后查 {SENDER_ACCOUNT} 的 INBOX ...")
    time.sleep(WAIT_SECONDS)
    im = imaplib.IMAP4_SSL(IMAP_HOST, IMAP_PORT, timeout=60)
    im.login(SENDER_ACCOUNT, SENDER_PASSWORD)
    im.select("INBOX")
    _, data = im.search(None, "ALL")
    uids = data[0].split()[-40:] if data and data[0] else []
    hit = None
    for u in uids:
        _, d = im.fetch(u, "(RFC822)")
        raw = d[0][1]
        if FID.encode() in raw:
            hit = raw
            break
    im.logout()
    return hit


def describe(raw):
    """打印退信的 MIME 形态，判断现有 parse_ndr 能否取到 fid。"""
    m = message_from_bytes(raw)
    print("   顶层 Content-Type :", m.get("Content-Type", ""))
    part_headers, text_has = [], False
    for p in m.walk():
        ct = p.get_content_type()
        part_headers.append(ct)
        if p.get("X-YXO-Forward-Id"):
            print("   ✅ 在部件 header 上找到 X-YXO-Forward-Id")
        if ct in ("text/plain", "text/rfc822-headers", "message/delivery-status"):
            body = (p.get_payload(decode=True) or b"").decode("utf-8", "replace")
            if "x-yxo-forward-id" in body.lower():
                text_has = True
                print(f"   ⚠️ 在【{ct} 正文】里发现 x-yxo-forward-id（说明现有解析器取不到！）")
    print("   部件类型清单     :", part_headers)
    return text_has


send_probe()
raw = scan_inbox()
print()
if not raw:
    print("=== 结论：❌ 收件箱里没找到含该 forward_id 的退信 ===")
    print("   可能原因：退信还没到 / 被投进「垃圾邮件」文件夹 / 退信没回传原信。")
    print("   请手动去 INBOX 和「垃圾邮件」里搜 '" + TAG + "' 再确认。")
else:
    print("=== 结论：✅ 退信已回到发信账号收件箱，且正文/头部含该 forward_id ===")
    text_has = describe(raw)
    print()
    print("   → 主键可用" if not text_has else
          "   → 主键可用，但【必须按 rev4 spec §2.3.1 加固 parse_ndr】才能取到")
```

## 三、还要顺手确认的两件事

1. **IMAP 登录是否可用**：脚本第 [2] 步就是在用该账号密码做 IMAP 登录。若报 `LOGIN failed` → 去邮箱后台开 IMAP 服务，或改用**客户端授权码**。这一步失败的话，整个四邮箱方案也不成立。
2. **退信落在哪个文件夹**：同事若配了规则把退信挪走，`BOUNCE_FOLDER` 就要跟着改。脚本默认查 `INBOX`，没找到时请**同时查「垃圾邮件」**。

## 四、把结果回给我（3 项）

1. 发信是否成功（`refused = {}`？）；
2. 退信是否到了发信账号 INBOX（或垃圾邮件）；
3. 脚本打印的 **MIME 形态**：`X-YXO-Forward-Id` 是在**部件 header** 上，还是在**正文文本**里？

第 3 项最关键：

| 结果 | 含义 | 对策 |
|---|---|---|
| 在部件 header 上 | 现有解析器就能取到 | 主键可用，按 rev4 实施 |
| 在正文文本里 | 现有解析器取不到 | 主键可用，但 **rev4 §2.3.1 的加固是必需的**（否则静默失效） |
| 完全找不到 | 对方没回传原信 | 主键失效 → 只能靠次键（rev4 §2.4），我再评估可靠性 |

## 附录A·RFC822 取信是否隐式置 \Seen 探针（rev4.1 §2.3）

RFC 3501 §6.4.5 规定 `RFC822` 等价 `BODY[]` 会隐式置 `\Seen` 标志。NDR 轮询已全部改用 `BODY.PEEK`（不置位），Idler（`core/ingest.py:277`）与 `fetch_raw_by_uid`
(同文件）仍在用 `(RFC822)`。先在生产环境实测服务端是否真会置位，再定 Idler 是否也改 PEEK：

```python
# 探针：RFC822 取信是否会把邮件标成已读
# 取一封未读邮件的 uid，记录其 FLAGS → 用 RFC822 取一次 → 再查 FLAGS
typ, d = conn.fetch(uid, "(FLAGS)")
print("before:", d)
conn.fetch(uid, "(RFC822)")
typ, d = conn.fetch(uid, "(FLAGS)")
print("after :", d)      # 若出现 \Seen → 服务端确认置位
```

结论回给芙蕾雅，用于决定 Idler 是否也要改为 `BODY.PEEK`（若置位则强烈建议改，否则业务文件夹的邮件会被静默标已读、`MarkSeenBatcher` 形同虚设）。
