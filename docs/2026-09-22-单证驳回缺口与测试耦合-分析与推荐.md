### 2.3 🔴 新系统现状：两个方案都不是（比她说的还偏一点）

我用代码路径走了一遍这封邮件（主题「单证审核驳回」、发件人 `docwbfb@yxologistics.com`、无附件、编码在正文）：

```

② 提取   ：waybill.py:45-69 —— 无 xls 附件 ⇒ 只从【主题】CODE_RE 取码 ⇒ code=None、box=None
           （第 16 行 body 读出来了，此后从未使用 ⇒ 正文里的编码没人看）
③ row_key：rowkey.py:14 → "0:no_key"
④ 路由   ：routing.py:177 → 无编码无箱号 ⇒ no_route
⑤ 落点   ：serve.py:375-385 —— 路由失败 ⇒ 记 ERROR「Routing failed: no_route」+ 入 error_queue
           + routing_failed 计数 + return "queued"
```

⇒ **实际行为 = 「ERROR 日志 + 错误队列，零业务通知」**。

**无论你怎么选，当前行为都要改**——它对一个**已知、且预期会来**的邮件类报"程序错误"，正是我们这批刚治过的同类噪音。

### 2.4 两个方案的实现形状（都不大）

**方案 1（推荐）：补实现 —— 仅通知负责同事，不转发、不进待办**

- `waybill.py`：主题含「单证审核驳回」时，**从正文**用 `CODE_RE` 取编码（照旧系统口径：`CODE_RE.search(body).group(0).split("-")[0]` ⇒ 取 `CQWLJT260917002` 这段），并打一个标记（如 `waybill_rejected=True`）。
- `serve.py::_process_row`：在**路由之前**加早分流（就放在现有 C2/W/OTHER 早分流旁边，`serve.py:299-308`）→ 用编码查到负责同事 → 发通知 → `return "alarm"`（或新词），**不进 error_queue**。
- 通知文案照旧系统：`🚨 单证审核驳回告警` + `客户编码: X` + `该客户单证审核被拒, 请尽快重报。`
- **⚠️ 一处必须提前讲清的差异**：旧系统的这条通知带「回复确认/跳过」，那条链路依赖 8765 回调，而**生产不通**（已知缺口）。⇒ 新系统只能做**单向告知**（不带确认/跳过）。你要么接受，要么把 8765 也列进来（那是另一件事）。

**方案 2：按 8-26 设计做"真忽略"**

- `waybill.py` 打标记 → `serve.py::_process_row` 的**同一个早分流**里并入 → `log.info` + `return "manual"`（"留人工、不标已读、不进错误队列"），**零通知**。
- 改动更小、且**完全复用现成机制**（顺序与语义都是现成的）。

> 两方案的差别只在"早分流那一步是发通知还是记日志"——**共同点是都必须在那一步拦住，不能再落到 routing 失败分支**。

## 3. 🟡 决策点 B：那条环境耦合的测试断言（我核实：她判断正确）

**失败项**：`test_p1_coverage.py::TestCredentials::test_fake_secrets_effective_and_real_untouched:391`

```python
assert accounts.get("maoxiaoyang@cqtransit.com") == "fake-pwd-mao"   # ← 这条是对的，保留
assert not (BASE_DIR / "secrets.json").exists()                      # ← 🔴 在部署机必红
```

**根因**：该断言的意图是"测试走假凭据、不碰真实文件"，但写法是"真实文件不存在"。
而 `secrets.json` **是部署机的运行必需品**（没有它收不到信）⇒ 只要在部署目录跑测试就必红。

**我建议的改法**（保留"能失败"的属性，而不是删掉了事）：

```python
real = BASE_DIR / "secrets.json"
before = (real.stat().st_mtime_ns, real.stat().st_size) if real.exists() else None   # 先拍快照
...
assert accounts.get("maoxiaoyang@cqtransit.com") == "fake-pwd-mao"   # 假凭据生效（不变）
assert sec_mod.SECRETS_PATH != real                                  # 环境无关：确实没指向真文件
after = (real.stat().st_mtime_ns, real.stat().st_size) if real.exists() else None
assert after == before                                              # 真文件既没被创建、也没被改动
```

要点：**两条断言都仍然"能被违反"**（若哪天 SECRETS_PATH 被改回真文件、或测试真的写了真文件，都会挂）；同时不再依赖"部署机上没有该文件"这个错误前提。

## 4. 🟡 决策点 C（我新发现）：测试往**生产日志目录**写，会污染我们刚加的 [7] 自检

**证据 1（配置）**：`config/settings.py:6-7`

```
DATA_DIR = BASE_DIR / "data"
LOGS_DIR = BASE_DIR / "logs"          # ← 硬编码，【没有】环境变量覆盖
```

而 `conftest.py:57-59,78` 只重定向了 `BOT_CONFIG_DB_PATH` / `DEDUP_DB_PATH` / `DAILY_COUNTERS_PATH` / `MAILBOT_SECRETS_PATH` —— **`LOGS_DIR` 没被重定向**。

**证据 2（实况）**：我本机 `mailbots_next/logs/mailbot_2026-09-22.log`（10,516 行）里出现测试数据：

```
ghost@example.com  × 10      boom × 16      fatal-id × 8
```

⇒ 小叽报告里那句"日志里另有 34 条 ERROR，绝大部分是测试用例产生的，需与真实运行区分"——**根因就在这里**。

**为什么必须修**：这直接**架空**我们刚加的 `§8 [7]`（"程序错误类告警应为 0 条"）——
她只要**先跑测试、再看日志**，[7] 就会报非 0，把一个正常的系统误判成"代码有问题"。**这正是我们这批反复在治的那类毛病：判据被环境噪音架空。**

**建议改法**（1 行配置 + 1 行 conftest，与既有做法一致）：

```python
# settings.py
LOGS_DIR = Path(os.environ.get("LOGS_DIR", str(BASE_DIR / "logs")))
# conftest.py（与第 57-59 行同一处）
os.environ.setdefault("LOGS_DIR", str(_TEST_DATA_DIR / "logs"))
```

顺带在 `§8 [7]` 的说明里补一句"**请先看日志再跑测试**（或跑测后换用新日志文件），避免测试噪音干扰判读"。
